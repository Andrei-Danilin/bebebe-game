# CLAUDE.md — bebebe-game (BeBeBe Atrapar)

A top-down 3D arcade game that Andrei makes with his kids from their scenario and drawings: the team of **Little Ones** (1–2 players + bots) against the **Big One**. Hug him from behind to take his hearts; if he sees you, he pushes you and your leg breaks; friends rescue you. The kids are the product owners: their decisions are the rules.

- **Game rules (source of truth):** `docs/game-design.md` — every rule says whose decision it is ("решение детей" / "придумал Claude"). A kids' rule never changes without a spec that says so.
- **Code map:** `docs/architecture.md` (sections of `index.html`, character states, the `window.__bb` debug object).
- **How work is run:** `docs/process/orchestration-rules.md` + `docs/process/run-templates/RUN_S|M|L.md`.

## What is in the repo

- `index.html` — **v2, 3D**: one HTML file, one ES module, no build step. Three.js **r187** is imported as the bare name `"three"`, resolved by one `<script type="importmap">` to jsDelivr (pinned `three@0.187.0`; SPEC-011); the game needs internet to load it the first time.
- PWA files: `manifest.webmanifest`, `sw.js` (offline cache), `icons/` (PNGs + the `icon.svg` favicon, all made from `art/2_icon.webp` by `npm run icons` with `sharp`). Published on GitHub Pages: **https://andrei-danilin.github.io/bebebe-game/** by `.github/workflows/pages.yml` on every push to `master`: the sharded tests and, in parallel, a `build` job (`npm run site -- --stamp <sha>` → `_site/` + `version.txt`), then `deploy` (two `deploy-pages` attempts, then a check that the live `version.txt` is this commit; SPEC-011). CI (SPEC-023): `.github/workflows/tests.yml` runs the whole suite in 4 shards plus a `lint` job (`npm run lint`) on every push of a `SPEC-*` branch (and is reused by `pages.yml`); `.github/workflows/balance.yml` makes the balance report on demand.
- Art (SPEC-020): `art/` — Andrei's source pictures (never written by code, not deployed); `scripts/assets.js` + the manifest `scripts/assets.json` turn them into `assets/*.webp` (committed, deployed, drawn by the 2D layer; every sprite has a code-drawn fallback). See `docs/architecture.md` "Art".
- `v1-2d/index.html` — v1, 2D canvas, offline. Frozen: no new features unless a spec names it.
- `tests/` — Playwright tests; every test opens the game over http from `scripts/serve.js` (SPEC-011; `pwa` = service worker and manifest; `modules` = the `__bb` surface, the import map, the lint config; `site` = the built `_site/` plays; `env` = GPU/priority of the test machine); three.js is served from `node_modules` so tests run offline. `tests/test-env.js` (GL backend, priority), `tests/global-setup.js`, `tests/pw.js` (failure screenshots).
- Tooling (SPEC-011): `scripts/site.js` (the one list of site files; `npm run site` → `_site/`, what Pages publishes), `scripts/lint.js` + `eslint.config.js` + `scripts/eslint-imports.js` (`npm run lint`: ESLint over the inline module of `index.html` and `scripts/`). Dev-only, not part of the site.
- `docs/` — `game-design.md` (rules), `architecture.md` (code map), `process/` (orchestration rules, run templates).
- `specs/` — `SPEC-NNN-*.md` (one feature each), `BACKLOG.md`, `_archive/` (done specs).
- `claude-setup/` — the committed source of the Claude Code agents and skills; `npm run claude:sync` copies them into `.claude/` (local, gitignored), where Claude Code finds them. Edit `claude-setup/`, never `.claude/` directly.

## Hard rules

1. **No build.** The site is `index.html` + `manifest.webmanifest` + `sw.js` + `icons/` + `assets/` (+ `v1-2d/`); `assets/` is generated by `npm run assets` and committed — the game itself needs no build step. The game still opens from disk by double-click (with internet for three.js) and publishes as one claude.ai page. No bundler, no framework, no new runtime dependency without a spec.
2. **Four languages for every string.** Every text a player sees goes into `I18N` for `en` (default), `es` (Argentina, voseo: "agarrá", "tenés", "campera"), `pt` (Brazil, pt-BR, *você*: "pegue", "você tem", "jaqueta"; SPEC-028) and `ru`; every name object (clothes, looks) has all four (`Nm(en, es, pt, ru)`). `tests/i18n.spec.js` fails on a missing key or name.
3. **Numbers live in `CFG`** (and `GLOVES`, `THEMES`, the outfit lists): no magic numbers in logic. A spec that changes a rule changes the `CFG` value and the line in `game-design.md`.
4. **JS style:** ES2022, `let`/`const` only (never `var`), short comments in Russian or English, code identifiers in English.
5. **Kid-friendly:** nothing scary or violent in visuals or texts (the Big One "pushes", nobody "dies"); big readable UI; works with touch, keyboard and gamepad.
6. **Keep `window.__bb` working.** Tests drive the game through it; a spec that adds state the tests need exposes it there.
7. **Progress is player data.** `localStorage` keys `bebebe-progress`, `bebebe-outfits`, `bebebe-place` (no longer read since SPEC-006; old saves may still have it), `bebebe-lang` (`en`/`es`/`pt`/`ru`), `bebebe-names`: a change to their shape keeps old saves loading (merge with defaults, never throw).
8. **`sw.js` `SW_VERSION` is bumped** when the precache list or a cache strategy changes (a change to `index.html` alone needs no bump: it is network-first). A new three.js version (the URL in the import map of `index.html` and `THREE_BASE` in `sw.js` must match — a test checks it) or a redrawn icon → bump. Sprites in `assets/` need no bump: `npm run assets` writes their list and `ASSETS_HASH` into `sw.js`, and the cache is named `SW_VERSION-ASSETS_HASH`, so installed apps fetch redrawn sprites.

## Workflow (spec-driven) and Git

**Roles.** Specs are written by Claude in the claude.ai project "BeBeBe Atrapar" (with Andrei and the kids) and committed to `master` as `specs/SPEC-NNN-short-name.md` before a run (that Claude cannot write into `.claude/` on this machine, which is why specs and docs live outside it). **Claude Code implements, commits and merges** — unlike ce-fsa-app, no user step is needed for commits or merges. Andrei starts a run by pasting the matching template from `docs/process/run-templates/` into `claude` at the repo root.

1. One feature = one spec (format: `specs/README.md`). Work strictly within one spec; anything new that comes up goes to `specs/BACKLOG.md`, not into the running spec.
2. **Branch** `SPEC-NNN-short-description` off `master` (`git branch --show-current` first; never edit on `master`).
3. **TDD**: for each acceptance criterion write the failing Playwright test first, then the code.
4. **Verify** (agent `tester`; speed rules, Andrei 2026-11-23): **no local whole suite.** Locally only `npm run test:fast` + the test files of what changed (`npx playwright test tests/<file>` or `-g "<name>"`); phone layouts locally at **667×375 only** (`-g "667"`; CI runs every size). **The whole suite runs on CI:** push the spec branch (`git push -u origin SPEC-NNN-...`, never `--force`), find the run of exactly that commit (`gh run list --workflow tests.yml --commit $(git rev-parse HEAD) --limit 1`, retried every ~10 s until it appears), then `gh run watch <id> --exit-status` the **Tests** workflow (`tests.yml`, 4 shards + `lint`); red → investigate from its artifacts (`gh run download <id>`: the merged HTML report, error context + failure screenshots), fix, push again. **The merge happens only when that run is green.** **Balance:** a spec that changes gameplay numbers or rules gets its report from GitHub: `gh workflow run balance.yml -f ref=<branch>`, `gh run list --workflow balance.yml --limit 5` → the run titled `Balance <branch>` created after the dispatch, `gh run watch <id> --exit-status`, `gh run download <id> -n balance -D reports`, commit the updated `reports/balance.md` + `reports/balance.json` on the branch, and list the red targets in its final report (red is not a stop by itself unless the spec's ACs say so); a changed number also needs `npm run docs:numbers`.
5. **Review**: **one pass** on `git diff master...<branch>` and the spec only — tiers M and L: `code-reviewer` + `architect-reviewer` **in parallel**; tier S: `code-reviewer` only. CRITICAL/HIGH are fixed in **one** fix round, then **one** check of the fix commits (`code-reviewer` on those commits only). No second full review.
6. **Commit** in small steps, explicit paths only, message `SPEC-NNN: <what>`, ending with the attribution lines from your system reminder. Use the machine's git identity; never change git config.
7. **Close on the branch, before the merge** (so close and merge go out in one push): agent `doc-keeper` updates `game-design.md`, `architecture.md`, `README.md` if the spec changed a rule, a structure or a command (commit `SPEC-NNN: docs`); the spec's `Status:` line becomes `done (merged by "Merge SPEC-NNN", see git log)` (the merge hash does not exist yet), the file moves to `specs/_archive/`, the run-state file `specs/SPEC-NNN_RUN_STATE.md` is deleted; commit `SPEC-NNN: close`; before this push, bring `master` in if it moved on — `git fetch origin && (git merge-base --is-ancestor origin/master HEAD || git merge origin/master)` (never rebase), so the merge result itself is tested; push the branch once — its Tests run (found by commit) must be green.
8. **Merge, push, deploy**: `git checkout master && git merge --ff-only origin/master && git merge --no-ff SPEC-NNN-...` (message `Merge SPEC-NNN: <title>`), then `git branch -d SPEC-NNN-...`; no local suite on `master` (CI tested the branch; the Pages workflow tests `master` again before the deploy). Remote `origin` = `github.com/Andrei-Danilin/bebebe-game`: `git push origin master` (never `--force`), then `git push origin --delete SPEC-NNN-...` (the remote spec branch), then find the Pages run of that commit (`id=$(gh run list --workflow pages.yml --commit $(git rev-parse HEAD) --limit 1 --json databaseId --jq '.[0].databaseId')`, retry until it appears) and `gh run watch $id --exit-status` until it (sharded tests + deploy) is green (a cancelled run = superseded by a newer push: watch the run of the last commit). A red deploy is reported, not retried blindly; the `deploy` job already tries `deploy-pages` twice and then checks that the live site serves the commit (SPEC-011). A red deploy **with green tests** ("Fetching artifact metadata failed" and the like) is recovered once with `gh run rerun <id> --failed` only when that run's `build` job was green and its commit is still the HEAD of `origin/master` (it reruns only `deploy`, which deploys the artifact `build` uploaded once); otherwise a fresh `gh workflow run pages.yml --ref master`. **Queues:** the next spec may start while the previous deploy is still running; its tests must be green before the next spec's own merge; a deploy-only failure with green tests does not block the next spec (Andrei). Final report: short table AC → test, test counts, CI run ids, review findings, open points.

Never: `git push --force`, pushing anything but `master` and your own spec branches (`SPEC-*`; never other people's branches), `git reset --hard`, `git branch -D`, rewriting history on `master`, editing `v1-2d/` or `node_modules/`.

## Commands

- First time on a machine: `npm run setup` (installs Playwright + three.js for tests, downloads Chromium, syncs `claude-setup/` into `.claude/`).
- Agents/skills changed in `claude-setup/`: `npm run claude:sync`.
- Balance report: on GitHub `gh workflow run balance.yml -f ref=<branch>` → `gh run list --workflow balance.yml --limit 5` → the run titled `Balance <branch>` created after the dispatch → `gh run watch <id>` → `gh run download <id> -n balance -D reports`; locally `npm run balance` (every level × 3 seeds with the autopilot in sim mode → `reports/balance.md`, `reports/balance.json`; targets in `CFG.BALANCE`). Not part of `npm test`; the CI sample is in `tests/balance.spec.js`.
- CI: the run of a commit `gh run list --workflow tests.yml --commit $(git rev-parse HEAD) --limit 1` (retry until it appears), `gh run watch <id> --exit-status`, `gh run download <id>` (artifacts: `html-report` = the merged Playwright report, `test-results-<n>` = error context + failure screenshots of shard n).
- Local test environment (SPEC-023): `PW_GPU` = auto (default: GPU locally, SwiftShader on CI) / `0` (force SwiftShader) / `1` (force GPU); `PW_NICE=0` keeps normal priority (default: the runner, its browsers and `npm run balance` run below normal; SwiftShader runs on a busy machine starve at below normal — use `PW_GPU=0 PW_NICE=0`). Claude Code itself at low priority on Windows: `start /belownormal claude --model opus`.
- Numbers section of `docs/game-design.md` (generated from `CFG`, `GLOVES`, `KISSES`, `RESCUE_KIT`): `npm run docs:numbers` (`--check` to only compare).
- Fast set while working (`@fast`, ~1.5 min): `npm run test:fast` · all tests: on CI (Tests workflow on the pushed branch); locally `npx playwright test` only when a spec asks for it (`workers: 1`) · one file: `npx playwright test tests/gameplay.spec.js` · one test: `npx playwright test -g "banana"` · watch it: `npx playwright test --headed`.
- Play locally: open `index.html` in a browser (Chrome/Edge/Safari/Firefox). Over http (service worker, manifest): `npm run serve` → http://localhost:8123/ (`PORT` to change it; Playwright starts it itself as `webServer`).
- Art (SPEC-020): a new or redrawn picture in `art/` → its entry in `scripts/assets.json` → `npm run assets` (writes `assets/`, the `ART_NAMES` list in `index.html`, the list and hash in `sw.js`; prints count, sizes, budget) → commit `assets/` with them. `node scripts/assets.js --debug <file>` lists the regions found on a sheet (to write the entry).
- App icon changed in `art/2_icon.webp`: `npm run icons` (`sharp`: `icon-192/512.png`, `apple-touch-icon.png`, `icon-512-maskable.png`, the `icon.svg` favicon) and bump `SW_VERSION`.
- Lint (SPEC-011): `npm run lint` (ESLint: `no-undef`, `no-unused-vars`, `no-var`, `prefer-const`, `no-import-assign`, unresolved imports; reports `index.html` line numbers). Runs as a job of every Tests run.
- Site build (SPEC-011): `npm run site` → `_site/` (gitignored; `-- --stamp <text>` writes `version.txt`, `--out <dir>`, `--no-pages`). A new site file goes into `SITE` in `scripts/site.js` (and into `sw.js`'s precache if the installed app needs it offline).
- Syntax check of the module without a browser: see `claude-setup/skills/game-verification/SKILL.md`.

## Test gotchas

- Locally the tests draw on the GPU, on CI with software WebGL (SwiftShader, slow per frame; `PW_GPU=0` locally does the same): gameplay is advanced with `step(page, seconds)` (logic only), not by waiting. A test that checks only logic or numbers opens the game in sim mode (`openGame(page, { sim: true })`, or the `simPage` fixture of the shared-page specs); in sim, `frames()`, `page.screenshot()` and the drawn state of `__bb` (`__bb.SIM_DRAWN`) throw — a test that checks drawing uses a rendered `page` (`docs/architecture.md` "Tests and CI").
- Specs require `./pw` (= `@playwright/test` + failure screenshots of every open page), not `@playwright/test` directly.
- Tests that change `__bb.CFG` restore it and call `__bb.clearLevelCache()` (the level cache keeps the accepted attempt per level).
- `openGame()` clears `localStorage` once per test; a test about saving reloads the page with `reloadGame(page)` (reload + wait for ready + seed again) and checks `window.__bb.progress`.
- Over http (SPEC-011): every test opens the game at `http://localhost:8123/index.html` (`PORT`); Playwright starts `scripts/serve.js` as its `webServer`, or reuses a running one only if it serves this checkout (header `X-Bebebe-Root`, checked in `tests/global-setup.js`; another checkout's `npm run serve` fails the run — stop it or set `PORT`). Service workers are blocked (`serviceWorkers: "block"` in `playwright.config.js`) except in `pwa.spec.js` (`openGameHttp()`).
- Seeds (SPEC-011): every test game is seeded from the test (FNV-1a of file name + title path, `testSeed()` in `helpers.js`): `openGame`/`openGameHttp` set `window.__bbSeed` so the boot is seeded too, then seed again; `resetGame`/`reloadGame` reseed. A failed test prints `[seed] … rng seed N`; a game is reproducible from it in sim only (a rendered page draws `rng()` in its frames). A smoke scan fails on a `startGame(`/`resetWorld(` with no seeded `seedRandom(n)` before it (or after a reload). Claims about a spread of outcomes run over several seeds with a bound.
- `tests/modules.spec.js` "the __bb surface is unchanged" compares `__bb` with `tests/fixtures/bb-keys.json` (key + kind: getter / getter+setter / function / value): adding keys is fine (add them to the fixture), removing one or downgrading its kind (a setter lost, a getter turned into a copied value) fails.
- A test that needs a calm Big One sets `big.state = "look"` and a large `big.timer`, and moves him away; bots keep moving — pin what you assert.
- If `CHROME_PATH` is set, Playwright uses that browser instead of its own Chromium.
- Speed (SPEC-018, `reports/test-times.md`): an `evaluate` never returns a game object — `evaluate(() => Object.assign(littles[i], …))` returns the Little One and Playwright serializes him with his 3D parts (11–15 s); put a mutating body in braces (a smoke test scans `tests/*.js`). Checks inside loops use `softly()` from `helpers.js` (or a problem list) and one `expect` at the end: each Playwright `expect` records a step. Never leave a second game page open while other tests run (it renders in software and slows them 3–5×). No screenshot per test by default: `PW_SCREENSHOT=only-on-failure npx playwright test …` to get them. `workers` stays 1 (2 workers ran each test twice as slow).
- Shared pages: `gameplay.spec.js` and the `?phone=1` tests of `phone.spec.js` share one game page (`sharedPage()` + `resetGame()` in `helpers.js`: a fresh game before each test; one shared page open at a time, closed before any fresh-page test). State a new test needs must be reset there too. `levels.spec.js`: the generator tests share one page (`levelPage` fixture, reset to Park 1 / English / level cache cleared before each); its fresh-page tests come first in the file. Save tests reload once and check other save shapes through `__bb.loadProgress(save)` (the pure merge the start code runs).
- PWA tests (`tests/pwa.spec.js`) use `openGameHttp()`: jsDelivr is routed at **context** level so the service worker's requests are intercepted too (`PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1`, set in `playwright.config.js`). The browser's own fetch of `sw.js` is not routable: a test that needs another `sw.js` starts its own `makeServer({ override })` from `scripts/serve.js`. `?standalone=1` makes `isStandalone()` true.
