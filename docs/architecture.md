# Architecture — bebebe-game v2 (3D)

One `index.html` (+ PWA files, see below): a small non-module script (offline hint) and one `<script type="module">` that imports Three.js r187 from jsDelivr. Two stacked canvases inside `#wrap`: `#gl` (WebGL, Three.js) below, `#game` (2D, UI and input) on top.

## Layers (keep them apart)
1. **Logic** — world, level generator (pure: no Three.js, no theme; the world only picks the seed), pathfinding, rules, bots, the Big One, items, progress. Works in "logic pixels": 960×640, `CELL = 32` (1 cell = 1 unit in 3D). Knows nothing about Three.js.
2. **3D** — builds meshes from the world (`buildMap3D`, `buildCharacters`) and copies state into them every frame (`syncScene` → `syncLittle`, `syncBig`, `syncItems`, `syncStars`, `syncKisses`, `updateCone`). Only reads game state.
3. **2D UI** — menus, HUD, name tags, timers, shop, skins screen, mini-map; positions of world things via `toScreen(x, y, heightPx)`. Buttons are registered each frame in `buttons[]` and hit-tested on `pointerdown`. Draws in **UI space** `UW × UH` (see Phone mode), never in world `W × H`.

## Worlds and level keys (SPEC-006)
- **A level is `(world, n)`**: `WORLDS = ["park", "school", "beach", "winter"]` (this order everywhere; the world is also the level's place, `THEMES[world]`), `n` = 1…`levelsPerWorld()` = `CFG.WORLD_TYPES.length` (20). `worldIndex(world)` (unknown → 0), `levelPos(n)` = clamped `n − 1`. **`levelKey(world, n)`** = `"world:n"` keys `levelCache` and the fixture.
- **Type and tier**: `levelType(world, n)` = `CFG.WORLD_TYPES[n − 1]` (same list in every world: 1 `classic`, 2–4 `meadow`, 5–7 `village`, 8–10 `river`, 11–13 `rooms`, 14–16 `arena`, 17–20 `maze`); `levelTier(world, n)` = position inside its block of one type (0…3). Each tier removes one bush (`bushCount`), never below `CFG.BUSH_MIN[type]`.
- **Seed**: `levelSeed(world, n)` = 1 for `n = 1` in every world (so every world's level 1 is the kids' drawing, Park level 1 = `tests/fixtures/level1.json`), else `(worldIndex + 1) × 100 + n`. The 3D decorations are seeded by the level number only (same `n` → same decorations in every world).
- **Current level**: `curWorld` + `level` (= n). `selectWorld(w)` (world card, ↑/↓, D-pad up/down via `cycleWorld(d)`) sets `curWorld`, saves `progress.lastWorld`, jumps to that world's `unlocked` level and calls `resetWorld`. `changeLevel(d)` clamps to 1…`worldProgress().unlocked`. `nextLevel()` after the last level → `toMenu()`. The old place picker (`PLACES`, `placeSel`, `cyclePlace`, `currentPlace`, key `bebebe-place`) is removed; `bebebe-place` is no longer read.
- **Difficulty** (logic section): **`difficulty(world, n, lost = 0)`** is the single source of the Big One's numbers → `{ chase, search, patrol, hearts, boost }`. `boost` = `levelBoost` (`CFG.WORLD_SPEED_START[w]` + `levelPos(n) × CFG.SPEED_PER_LEVEL`) + `floor(lost) × CFG.BIG_SPEED_PER_HIT` (uncapped); `chase` = `BIG_CHASE_SPEED + boost`, `search` = `BIG_CHASE_SPEED × 0.85 + boost`, `patrol` = `BIG_PATROL_SPEED + boost × 0.5`, each through `chaseCap` = `min(CFG.BIG_CHASE_MAX, v)`; `hearts` = `bigHearts` = `min(BIG_HP_MAX, BIG_HP + floor(levelPos / HP_LEVELS_PER_HEART) + w × HP_PER_WORLD)`. `CFG.BIG_CHASE_MAX` is a getter = `CHASE_MAX_SHARE × PLAYER_SPEED` (142.5) — derived; change `CHASE_MAX_SHARE`. `resetWorld` takes `big.maxHp` from `difficulty(curWorld, level).hearts`; `bigDifficulty()` = `difficulty(curWorld, level, big.maxHp − big.hp)`; `bigSpeeds()` → `{ chase, search, patrol }` used by `updateBig`; `bigBoost()` = its `boost`. The ×0.85 and ½ factors are literals (not `CFG`).
- **Menu and win screen**: `worldCard(w, x, y, cw, ch)` draws one card (`worldPicture` from `THEMES[w]` colours, name, `worldStars(worldStarsOf(w), STARS_PER_LEVEL × 20)`), pushes a button `world:<w>` → `selectWorld(w)` and a record into `worldCards` `{ world, x, y, w, h, name, stars, selected }` (reset each frame in `drawUI`). Desktop: four cards in a row under the rules, the level selector and type label under them; phone: 2×2 cards in the right column. The total ⭐ counter next to the coins stays. `winText()` sets `winLine` = `worldDone(worlds[w], w)` after the last level (Russian gender by key), else `winSub`. `endActions("win")` after level 20 returns Menu (green, also Enter / pad A) + Shop only; desktop then uses a two-button layout.

## Level types and the generator (SPEC-002)
- **`generateLevel(world, lv, attempt)`** (pure, theme-free, seeded only by `mulberry32(levelSeed(world, lv) * 7919 + attempt * 104729 + 13)`): builds the layout context `lc` (`lv, attempt, type, tier, rng, ri, items, occ, reserve, isFree, hWall, vWall, place(n, make, w, h, m, ok)`, `small`, `bigPt`, `doors`, `homes`, `meta`) → **`placeHomes(lc, variant)`** (Little Ones' house 7×6 top-left with `safe`, beds and spawns; the Big One's 6×6 house through `bigHouse()` bottom-left `"side"` or bottom-right `"diagonal"`; `CFG.DOOR_APRON` cells reserved in front of every door; `variant` = `"side"` for classic, `CFG.LAYOUT[type].homes` if set, else the seed) → **`LAYOUTS[type](lc)`** → mirror `fx`/`fy` (not on level 1; mirrors items, danger `exits`, `meta.areas` and the doors) → flowers. Returns `{ type, items, small, big, flowers, doors: { small, big }, meta }`; `doors` = door openings `{ x, y, w, h, dx, dy }` (outward direction) for the fairness rules; `meta` = layout facts (`deadEndsBefore/After` for the maze, `areas` — plazas, bridges, rooms + doors, arena block/ring/gaps — for tests, `bad` = the layout could not be built, `vertical` for the river).
- **Layouts** (all sizes in `CFG.LAYOUT[type]`): `classicLayout` = the old body, byte-for-byte (fixture `tests/fixtures/level1.json`); `meadowLayout` (ponds, trees, rocks, bushes); `mazeLayout` (3-cell modules: Kruskal perfect maze, home areas and 5×5 plazas opened, braided to ≤ `CFG.MAZE_DEAD_ENDS`, walls as `maze` cells); `villageLayout` (`floor` `square` + fountain `pond`, `cottage` blocks with `street` margin, bushes next to cottages); `riverLayout` (`water` pieces between the houses, bends, `floor` `bridge` with `across: "x"|"y"`, bushes split between banks); `roomsLayout` (diagonal only: two wings with BSP rooms, `build` walls, `tile` floor, outside doors into both yards); `arenaLayout` (diagonal only: `arena` block and ring with gaps, optional half-ring). `emitWalls(items, occ, wall, kind)` turns a wall-cell grid into wall rectangles.
- **Item kinds and flags** (`applyWorld` → `obstacles`): `wall` kinds `home`/`bighome`/`build`/**`maze`**/**`arena`** (and `hedge` from the fallback) — move + sight; **`cottage`** — rect, move + sight; **`water`** — rect, move only (sight passes); `pond` — move only, `fountain: true` for the village fountain; `tree`/`rock` — circles, both. `floor` kinds `wood`/`tile`/**`bridge`** (`across` kept)/**`square`** are walkable ground only. Bridges are gaps between water pieces, so they are free cells.
- **`buildGrids()`** rasterizes: each obstacle marks only the fine/coarse cells of its own bounding box (same rules as `covers()`), because a level may be built up to `CFG.LEVEL_ATTEMPTS` times; then `moveGridBig`/`blockedBig` add the safe zone.
- **`validateLevel(gen, type)`** (on the applied world) → `{ ok, fails, seen, freeRatio, bigReachAll, smallReachAll, housePath, doorClear, deadEnds: { count, longest, before }, bushes }`. Rules: `smallReach` (`connectivity()`), `bigReach` (`floodCells` on `blockedBig` from his spawn), `housePath` (A* on `blockedBig`, √2 diagonal, shortest big-door → cell-in-front-of-small-door pair, in `CFG.HOUSE_PATH`; skipped for `classic`), `free` (`CFG.FREE_MIN[type]`, outside both houses), `doors` (`CFG.DOOR_APRON` rows in front of every door free on both grids), `deadEnds` (`deadEndScan`: 2×2 free windows of `blockedBig` as nodes, leaves peeled; maze: count outside houses and aprons ≤ `floor(before × MAZE_DEAD_ENDS)`, others: `longest ≤ CFG.DEAD_END_MAX`), `bushes` (`CFG.BUSH_MIN`), plus `layout:<meta.bad>`.
- **`buildLevel(world, lv)`**: attempts 0…`LEVEL_ATTEMPTS - 1`, first `ok` wins. Fallback: rebuild the attempt with the lowest `failScore` (fail count, +100 if a reach rule failed), fill with `hedge` every free cell the Little Ones can't reach or (outside their house) the Big One can't reach, `console.warn`. Sets `reachable`; returns the report without `seen`/`ok`, plus `tier`, `attempt`, `attempts`, `fallback`, `rejects`, `ms`.
- **`loadLevel(world, lv)`** (from `resetWorld`, with `curWorld, level`): `levelCache` (`levelKey(world, lv)` → accepted attempt) rebuilds that attempt directly and re-validates it; a cached attempt that no longer passes (e.g. `CFG` changed) is dropped and the level is built from attempt 0. Fallback results are not cached. Sets **`levelInfo`** `{ world, lv, type, attempt, fallback, cached, ms }`. `clearLevelCache()` empties the cache.
- **`levelReport(world, lv)`** (tests): saves the world (`keep` = `obstacles, bushes, floors, decor, trees, flowers, safeZone, dangerZone, spawns, reachable` + copies of the five grids), runs `buildLevel`, restores everything in `finally`. The comment above `applyWorld` says it: new world state → add it to `keep` and to `__bb.worldState`.
- **Bots on new layouts**: `fleePoint` only picks `reachable` cells and falls back to `freePointNear`; `lurkPoint` snaps to `freePointNear(p)` (nearest free reachable cell via `freeCellNear`), so targets are never inside walls or across water.
- **3D** (`buildMap3D`): the place is the built level's world (`levelInfo.world`, else `curWorld`); `builtKey = mapKey()` = `levelInfo` `world:lv:attempt:fallback`, and `rebuild3D` rebuilds the map only when `mapKey()` changes. `cottage` → `makeCottage` (body, pitched roof along the long side, snow on winter roofs, door, windows); `water` → `makeWaterFor` (flat, no rim, so pieces join into one river; waves except winter) + `riverBanks` (one `InstancedMesh` of edge strips on water sides not next to water, a bridge or the map edge; stone edge in the schoolyard); fountain `pond` → `makeFountain` (bowl, water, column, bobbing drop in `waves`, `userData.baseY`); `maze` walls → boxes in `THEMES[place].maze` colours + `mazeDeco` (`InstancedMesh`: bumps, posts, snowballs, locker seams); `arena` walls via `walls.arena`. Maze walls keep `WALL_H` 0.85 (characters stay visible). `paintGround` draws `bridge` planks (across the crossing) and `square` cobbles. `tag(mesh, piece)` sets `userData.piece` for `__bb.mapPieces()`; `disposeTree` also disposes `InstancedMesh` buffers.
- **Theme keys** (`THEMES[place]`): `walls.arena` `[wall, top]`; `maze` `{ wall, cap, deco: "bumps"|"posts"|"snow"|"seams", decoC }`; `cottage` `{ wall, roof, door, window, snow? }`; `water` `{ c, edge, stone?, waves, wave }`; `bridge` `[plank, gap]`; `square` `[base, stone]`; `fountain` (bowl colour).

## Phone mode (SPEC-005)
- **Detection**: `isPhone()` (screen section) = `?phone=1` → true, `?phone=0` → false, else `isTouch && min(screen.width, screen.height) <= CFG.PHONE_MAX_SHORT_SIDE`. Computed once into **`PHONE`** (like `STANDALONE`); `PHONE` adds `body.phone` (CSS: `#wrap` without rounded corners and shadow). With `PHONE` false every code path is the desktop one.
- **World vs UI space** (the rule): `W`/`H` = the world, always 960×640 (map 30×20 × `CELL`). `UW`/`UH` = the UI layer's logical size: on desktop `UW = W`, `UH = H`; on a phone `UH = CFG.PHONE_UI_H` (420) and `UW = UH × CSS_W / CSS_H` (unrounded). Every UI drawing, hit-test and `toScreen` result is in UI px; world logic uses `W`/`H`. `toGame(e)` maps pointers into UI px; `VIEW` = canvas px per UI px.
- **`fit()`**: desktop letterboxes `W × H` into `playArea()`; a phone fills `playArea()` (no bars). Then the **`onFit`** hook (set in the 3D section, phone only): camera aspect = canvas shape, `fitCamera()` again (full-map distance `cam.dFull`), visible-ground trapezoid (`groundCorners` → `camOff`), follow distance `cam.dFollow` = `CFG.PHONE_VIEW_ROWS` rows tall, `camProbe` for `uiOf`, the shadow box. - **Sizes in CSS px**: `cpx(n)` = n CSS px in UI px; `minPx(cat)` = the smallest text of a kind (`CFG.PHONE_TEXT`: `title` 24, `main` 15, `hint` 13, `input` 16). `fz(size, cat)` returns `size` on desktop, on a phone at least `minPx(cat)`, and records it. `textSizes` = the smallest size drawn this frame per kind (+ `drawn` from `label`/`fitText`), reset in `drawUI`; tests read it.
- **Camera** (3D section, «Камера телефона»): `cam = { x, y, lax, lay, zoom, dFollow, dFull, full }`. `cam.zoom` 0 = follow the hero, 1 = whole map; it goes to 1 outside `play`/`pause` (menu, skins, shop, win) and back to 0 in play over `CFG.CAM_ZOOM_TIME` (smoothstep). **`updateCamera(dt)`** is called from `frame()` after the logic, **not** from `update` (the tests' `step()` does not move the camera; they call `__bb.updateCamera`). It eases the look-ahead (`CFG.CAM_LOOKAHEAD`, `CAM_LOOKAHEAD_RATE`; only while the hero walks in state `ok`, not hugging) and the target (`CFG.CAM_FOLLOW`, frame-rate independent `1 − e^(−k·dt)`), then `applyCamera()`. **`camSnap()`** (from `startGame`) puts the camera on the hero at once, zoom 0. `camHero()` = the first `player`. - **`followGoal(l, x, y)`**: `clampLook` keeps the visible ground at most `CFG.CAM_EDGE` cells past the map edge. ## Randomness (SPEC-008)
- **Gameplay** randomness goes only through **`rng()`** (helpers section; a `mulberry32`, randomly seeded at start, so normal play is as before). `rand(a, b)` draws from `rng()`. Users: item and star spawns (`spawnItem`, `spawnStar`), `randomFreePoint`, the Big One's look timers and `lookSign`, bot timers (`botWait`, lurk, `botAttackCd`), `makeLittle`, `resetWorld`, `steerPoint`'s default repath delay. **`seedRandom(n)`** reseeds it (`seedRandom()` without a number → random again). Same seed + same inputs → the same game.
- **Visual** randomness uses **`vrand(a = 0, b = 1)`** on `Math.random`: `burst` particles, the hearts during the hug ride, camera shake in `syncScene`, snow in `buildMap3D`, `randomOutfit`. It never touches `rng()`, so sim mode (no particles) draws the same `rng()` sequence as normal play. The level generator and the 3D decorations keep their own seeded `mulberry32`.
- **Guard**: `noGameRng(name, fn)` sets `rngOff = name` while `fn` runs. It wraps `generateLevel` (→ `layoutLevel`), `rebuild3D` and the render half of `frame()`. A `rng()` call inside it: with **`strictRng`** on (tests: `openGame` sets `window.__bbStrictRng` by an init script, the game reads it at start) it throws `"<name>: gameplay rng() used; …"`; in normal play it falls back to `vrand()`, so the level still starts and the gameplay sequence is not consumed.
- `rngDraws` counts gameplay draws (a test checks that the autopilot's decision draws none).
- `tests/balance.spec.js` "same seed, same game" (`@fast`) also scans `index.html`: `Math.random` is allowed only in the `rngNext` seed and in `vrand`.

## Sim mode and the event log (SPEC-008)
- **Sim mode**: `simMode` = `?sim=1` (`openSim(page)` in `tests/helpers.js` = `openGame` with that query) or `sim(true)`. In sim: `frame()` only requests the next frame (no `update`, no drawing), `rebuild3D` returns at once, `burst` makes no particles, `initAudio`/`soundOn()` play nothing. `sim(false)` rebuilds the 3D scene. `sim(on?)` → `{ on, renders, draws, sounds }` (counters for the test: `render3D` calls, `drawUI` calls, sound requests outside sim).
- **`simRun(seconds, dt = CFG.BALANCE.SIM_DT)`** calls `update(dt)` in a loop while `mode === "play"`, at most `round(seconds / dt)` steps → plain `{ ended, win, time }`. A deterministic run = `seedRandom` + `startGame` + `simRun` inside one `page.evaluate` (no real frames between them).
- **Event log** (characters section): `events` = `[{ t, type, …data }]`, plain data only, added by `logEvent(type, data)`. `t` = `stats.time` (game seconds since the last `resetWorld`). Capped at `CFG.EVENT_LOG_MAX` (5000; the oldest drop out); cleared in `startGame` (not in `resetWorld`, so shop buys between levels are logged until the next level starts).
- **Event types**: `hug { power, who, kind }`, `push { who, blocked }` (`blocked` = the shield took it), `down { who, kind }`, `rescued { who, by: "bot"|"player" }`, `rest { who }`, `back { who }`, `kiss { who, result: "hit", blush }` / `kiss { who, result: "miss" }`, `kit { who }`, `star { who }`, `item { kind, who }`, `slip {}`, `thrownOut { who }`, `win {}`. `who` = the Little One's `id`.
- **`coins { reason, amount }`** (`logCoins`, called only by `addCoins`/`spendCoins` — see Coins economy) at every change of `progress.coins`. Reasons (SPEC-009): `firstWin` or `replay`, `newStars`, `hugs`, `rests` (negative) — the win lines of `giveReward(true)`; `hugs` from `giveReward(false)` (leaving a level); `star` (+`STAR_COINS`) at pickup in `updateStars`; purchases with the negative price: `buy:mittens|mega|kisses|rescues`, `buy:hat:<id>`, `buy:jacket:<id>`, `buy:pants:<id>`, `buy:big:<id>`, `buy:upgrade:<key>`. Zero amounts are not logged. The sum of `coins` events = the change of `progress.coins`.
- **`lastReward.parts`** = `[{ reason, amount }]` in win-screen order: `firstWin`|`replay`, `newStars`, `star` (= `stats.starCoins`; no `coins` event for it at the win — that was logged at pickup), `hugs`, `rests`; zero parts left out. `lastReward.coins` = the sum of `parts`. On leaving early: `hugs` and `star` parts.

## Autopilot (SPEC-008)
- Logic section, before `updateBig`. Drives the **player** Little Ones for balance runs and tests; bots keep their own AI. It acts only like a player: **`autoMove[pi]`** = `{ x, y }` (length ≤ 1), which **`inputFor(l)`** adds like one more stick, and the buttons `throwKiss(pi)` / `useRescueKit(pi)` (only when `canUseKit`). It never writes the Big One's, the bots' or the Little Ones' state, `CFG` or `progress`, and draws no `rng()`.
- **`autopilot(on?, style?)`** → `{ on, style }`; style `"careful"` (default) or `"reckless"`; off clears `autoMove`. **`autoThink(dt)`** (called by `update` before `updatePlayers`; only in `play`) rebuilds `autoMove` every step.
- **`autoNavs`** (Map by player id → `{ x, y, r, path, repath }`, via `autoNav(l)`) is the autopilot's own path memory, so it never writes `l.path`. Paths come from **`steerPoint(e, gx, gy, dt, avoidCone, repathIn)`** — the target-point half of `steerTo` (A* with the bots' cone and danger costs), split out so the autopilot can use it with a fixed repath delay (`CFG.AUTOPILOT.repath`) instead of `rand()`. `steerTo` = `steerPoint` + the move. `resetWorld` resets `autoNavs` and `autoMove`.
- **careful** (`autoGoalCareful`): a slipped Big One → straight at him; else a downed friend no bot is closer to (unless the Big One is dangerous and near him); else a bonus star or a non-banana item within reach while he can't see it; else his back (`backPoint`) — from far along a path around his view, near and in front of him circling sideways. `bigDangerous()` = no stun, slip, blush, `pushCd` or `noPush`. Kit: when it can use one and has waited `kitWait` s unhelped (or is already limping/resting). Kiss: facing him, in range, line of sight, he can be blushed.
- **reckless** (`autoGoalReckless`): straight to his back, no hiding, no rescues, no buttons.
- All its distances and times are in **`CFG.AUTOPILOT`** (`repath`, `itemReach`, `pickSafe`, `rescueSafe`, `sneakNear`, `orbit`, `orbitStep`, `orbitR`, `arrive`, `backNear`, `backDist`, `hugIn`, `minStep`, `kitWait`, `kissAim`, `kissReach`).

## Coins economy (SPEC-009)
- **Ledger**: **`addCoins(reason, amount)`** and **`spendCoins(item, amount)`** (progress section) are the only code that changes `progress.coins`. `addCoins` clamps the amount so the coins never go below 0, skips 0, adds, `logCoins(reason, amount)`, saves, returns what it added. `spendCoins` returns `false` and changes nothing when the coins are short; else subtracts, logs `buy:<item>` with the negative amount, saves, returns `true`. `logCoins` pushes the `coins` event into `events` (via `logEvent`) and a copy into **`ledger`** — the session list since page load (not cleared by `startGame`, capped at `CFG.EVENT_LOG_MAX`; `__bb.ledger()` returns copies). Callers: `giveReward`, `updateStars`, `buyGloves`/`buyKisses`/`buyRescueKit` (`spendCoins(kind, price)`), `buyLook` (`spendCoins("<slot>:<id>", price)`), `buyUpgrade` (`spendCoins("upgrade:<key>", price)`). Reasons: see the event log.
- **Source scan**: `tests/economy.spec.js` "only the ledger writes coins" (`@fast`, Node, `coinWrites(src)`) fails on any write to a `coins` member outside the bodies of `addCoins`/`spendCoins` — `=`, compound `op=`, `++`/`--`, `["coins"]`, aliases, destructuring targets, `Object.assign(…, { coins })`, `Reflect.set`/`Reflect.defineProperty`/`Object.defineProperty`, and `progress = …` other than `freshProgress()` / `loadProgress(…)` or a `...progress` spread; it plants one write of each kind to prove the scan finds it. Tests may still set `__bb.progress.coins` as setup.
- **Reward** (`giveReward(win)`): `rewardBase(wi, n)` = `REWARD.BASE + PER_LEVEL × n + PER_WORLD × wi`. Win: `first = !worldProgress().won[n]`; the line = `max(base, FIRST_MIN)` or `max(floor(base / 2), REPLAY_MIN)`; `restCut = min(rests × CFG.COINS_PER_REST, line − floor)`, so the shown lines always add up; `newStars = max(0, stars − previous best)` × `REWARD.NEW_STAR`; `hugs = stats.playerHugs × REWARD.PER_HUG`. Every part except `star` goes through `addCoins` (one ledger entry per line); stars, `won[n] = true` and `unlocked` are written to the current world. `lastReward` = `{ win, coins, starCoins, stars, nobodyOut, fast, target, first, base, newStars, newBest, world, level, worldDone, parts }`. Not a win: `addCoins("hugs", …)`, `lastReward = { win: false, coins, starCoins, parts }`.
- **Reward lifecycle**: **`rewardDue`** = a level is running and not paid yet: `startGame` sets it; `giveReward`, `resetProgress` and `__bb.setProgress` clear it. **`leaveLevel()`** (first thing in `startGame` and `toMenu`; so pause → Menu, a restart, the next level) does nothing unless `rewardDue` and the mode is `play`/`pause`; with `pendingWin > 0` (the last heart is gone, the final hug still playing) it clears `pendingWin`, logs `win` and pays `giveReward(true)`; otherwise `giveReward(false)` (hugs only). The win path through `winSoon`/`pendingWin` pays once, because `giveReward` clears `rewardDue`.
- **Wardrobe**: hats/jackets/pants/Big One looks have `id` and `price` (`tierPrice(0…3)`, 0 = free; hairs are always free). **`skinSel`** = what is shown (may include a locked item while trying on), **`skinKeep`** = the last own look (owned or free): `bebebe-outfits` stores `skinKeep` (`saveSkins`) and a level starts with it. `ownsItem(slot, idx)` = free or the id is in `progress.owned[OWN_KEY[slot]]`. `cycleOutfit`/`cycleBig` move `skinSel`; an owned item goes into `skinKeep` at once. `tryingOn` (`updateTryOn`) = some column (`p1`, `p2`, `big`) shows a locked item; `lockedItems(key)` / `lockedPrice(key)`. **`buyLook(key)`**: short of coins → `buyArmed = null`, `SFX.out`; first call arms (`buyArmed = key`), the second buys every locked item of that column through `spendCoins` and moves them into `skinKeep`. **`endTryOn()`** (from `startGame` and from `frame()` when the mode is not `skins`/`names`) puts `skinSel` back to `skinKeep`. `randomOutfit` picks only owned items; `botOutfit(i)` may use any. `fitOutfitsToOwned()` (after `resetProgress`, or at start for a save that has `owned`) replaces a not-owned kept item with its `DEFAULT_SKINS` one. `resetOutfits()` (tests) = default looks, nothing tried on.
- **Upgrades**: `progress.upgrades = { fastFeet, longItems, quickHelp }` (0…`upgTop(k)`). **`buyUpgrade(k)`**: unknown key or top level → nothing; short of coins → `SFX.out`; else `spendCoins("upgrade:" + k, prices[lv])`, level + 1, saved. `makeLittle` copies the levels into **`l.upg`** for a `player` (bots: `null`), so a level keeps the upgrades it started with. **`playerBonus(l, k)`** = `l.upg[k] × UPGRADES[k].step` (0 for bots). **`moveSpeed(l)`** = `CFG.PLAYER_SPEED × (1 + fastFeet bonus) × BOOTS_MULT` while boots (used by `updatePlayers` and the autopilot) — `CFG.PLAYER_SPEED` and so `BIG_CHASE_MAX` never change. `updateItems`: a boots/cloak/shield effect lasts `base × (1 + longItems bonus)`; `ITEM_LIFE` unchanged. `updateDowned`: the helper is a player next to him if any, else a bot; **`l.rescueNeed`** = `CFG.RESCUE_TIME × (1 − quickHelp bonus of that helper)`; the rescue ring in `drawMarkers` fills to `rescueNeed`.
- **Shop tabs**: **`shopTab`** = `"items"` | `"upgrades"` (`drawUI` sets it back to `items` outside the shop; `switchShopTab()` from ←/→ and D-pad 14/15). `shopTabs(x, y, h, …)` draws the two tab buttons (ids `tab:items`, `tab:upgrades`) where the title was; desktop: tabs (with 🛒/⭐) and the coins plate in the 880 px panel; phone: tabs, coins plate, Reset and OK in one top row (≥ `PHONE_BTN_MIN`), the cards under it. **Upgrades tab**: `upgradeCards()` → `{ k, lv, top, name, desc, price, dots }`; each card: emoji picture (`UPG_ICONS`), name, level dots (`upgDots`, ●●○), effect text, `upgButton` ("Buy N 🪙" green / grey when short, "✔ Max" at the top; id `upg:<k>`), "not enough coins" under it. Desktop `upgradeCardsDesktop()`: three cards of `(850 − 2 × 10) / 3` px. Phone `upgradeCardsPhone()`: measured with `pRows` (× `TEXT_TEST_SCALE`) and drawn with `pDraw` like the item cards; when they don't fit, the picture shrinks to `picMin`, then description and name lose rows, then the picture goes below `picMin`; `shopLayout = { tab: "upgrades", step, picH }`. Parts in `hudRects`: `upg-pic|upg-name|upg-dots|upg-desc|upg-no:<k>`. The Items tab keeps the four cards and the SPEC-007 degrade order under the tab row.
- **Skins screen** (wardrobe UI): a locked row shows `🔒 <price> · <slot>` (`rowLock`, `slotText`); the coins plate (`coinPlate`, `hudRects` id `coins`); while a column has locked items `lookBuy(key, …)` replaces its name label with the "🔒 Buy for N" button (id `buy-look:<key>`, red "✔ …" when armed) and `previewNote` shows "not enough coins" or "Tap again to buy" (`hudRects` `look-note:<key>`; desktop over the bottom of the preview, phone under it).
- **Win screen lines**: **`drawRewardLines(rw, x, y, w, rowH, size, min, big, bigMin)`** draws one row per `lastReward.parts` entry — `RW_ICONS[reason]` + `rw[reason]` on the left, `+N` / `−N` on the right (negative in red) — then a rule and the total with a coin. Each text is measured × `CFG.TEXT_TEST_SCALE` and shrunk to `min`, then cut with "…" (`fitLine`). `hudRects`: `win-line:<reason>` (name), `win-num:<reason>` (amount), `win-line:total`, `win-num:total`; **`winPanel`** `{ x, y, w, h }` = the box of all rows. Desktop: stars and ✔/✘ on the left, lines at `UW / 2 + 20`, 340 px wide; phone: in its right column.

## Save data (localStorage)
- `bebebe-progress` (SPEC-006, SPEC-009): `{ worlds: { park|school|beach|winter: { unlocked: 1..20, stars: { [n]: 1..3 }, won: { [n]: true } } }, lastWorld, coins, inv: {mittens, mega, kisses, rescues}, equip: [p1, p2], owned: { hats: [id], jackets: [id], pants: [id], big: [id] }, upgrades: { fastFeet, longItems, quickHelp } }`. Defaults come from `freshProgress()` (every world `freshWorld()` = `{ unlocked: 1, stars: {}, won: {} }`; `owned` empty lists, `upgrades` all 0; also used by `resetProgress`, which keeps `lastWorld` = the shown world). **`loadProgress(pv)`** never throws: each world goes through `cleanWorld` (broken → default, `unlocked` clamped to 1…20, stars only for n 1…20, capped at `CFG.STARS_PER_LEVEL`); unknown `lastWorld` → `park`; `inv` merged with defaults and `inv.kisses`/`inv.rescues` forced to whole numbers ≥ 0 (missing → 0); SPEC-009: `coins` → a whole number ≥ 0 (`wholeCoins`); `won` keeps only `true` for n 1…20, and **every level with stars counts as won** (old saves); `owned` → `cleanOwned` (only ids of paid items of that list, no repeats, broken → empty); `upgrades` → `cleanUpgrades` (whole numbers 0…top, broken → 0). **Migration**: a save with the old flat `unlocked`/`stars` (`hasFlatProgress`) moves them into the Park (`unlocked` → min(20, old), stars for n ≤ 20, higher levels dropped); if it also has `worlds` (an old tab wrote the flat fields back), they merge into the Park — the larger `unlocked`, the best stars per level. The flat fields are left out of the result, and a migrated save is written back once on load. Coins, inventory, equip and names are untouched. `giveReward` writes stars/`won`/`unlocked` only into `worldProgress()` (the current world) and sets `lastWorld`; coins — see Coins economy; fast time `FAST_TIME(n) + w × FAST_PER_WORLD`. Every known old save shape is a fixture in `tests/fixtures/saves/` (SPEC-008).
- `bebebe-outfits`: `{ p1: {hair, hat, jacket, pants}, p2: {...}, big }` — **indexes** into `HAIRS`/`HATS`/`JACKETS`/`PANTS`/`BIG_SKINS` (shape unchanged by SPEC-009), read at start into `skinSel` (clamped) and copied to `skinKeep`; it always stores `skinKeep`, so never a locked item. **Outfit adoption** (SPEC-009, at start): a progress save **without** an `owned` field (`hadOwned` false: before SPEC-009 everything was free) gets the worn paid items added to `owned` (`adoptWorn`, saved once); a save **with** `owned` goes through `fitOutfitsToOwned` (a worn item not owned is taken off, not given away). Needs a real reload: outfits are not part of `loadProgress`. `bebebe-place`: no longer read (SPEC-006: the place is the world); old saves may still have it. `bebebe-lang`: `en|es|ru`.
- `bebebe-names` (SPEC-003): `{ p1, p2, big, bots: [b1, b2, b3, b4] }` — only typed names, `""` = language default; every field cleaned on load, missing or broken data → defaults.
