# Architecture — bebebe-game v2 (3D)

One `index.html` (+ PWA files, see below): a small non-module script (offline hint) and one `<script type="module">` that imports Three.js r187 from jsDelivr. Two stacked canvases inside `#wrap`: `#gl` (WebGL, Three.js) below, `#game` (2D, UI and input) on top.

## Layers (keep them apart)
1. **Logic** — world, level generator (pure: no Three.js, no theme; the world only picks the seed), pathfinding, rules, bots, the Big One, items, progress. Works in "logic pixels": 960×640, `CELL = 32` (1 cell = 1 unit in 3D). Knows nothing about Three.js.
2. **3D** — builds meshes from the world (`buildMap3D`, `buildCharacters`) and copies state into them every frame (`syncScene` → `syncLittle`, `syncBig`, `syncItems`, `syncStars`, `syncKisses`, `updateCone`). Only reads game state.
3. **2D UI** — menus, HUD, name tags, timers, shop, skins screen, mini-map; positions of world things via `toScreen(x, y, heightPx)`. Buttons are registered each frame in `buttons[]` and hit-tested on `pointerdown`. Draws in **UI space** `UW × UH` (see Phone mode), never in world `W × H`.

## Worlds and level keys (SPEC-006)
- **A level is `(world, n)`**: `WORLDS = ["park", "school", "beach", "winter"]` (this order everywhere; the world is also the level's place, `THEMES[world]`), `n` = 1…`levelsPerWorld()` = `CFG.WORLD_TYPES.length` (20). `worldIndex(world)` (unknown → 0), `levelPos(n)` = clamped `n − 1`. **`levelKey(world, n)`** = `"world:n"` keys `levelCache` and the fixture.
- **Type and tier**: `levelType(world, n)` = `CFG.WORLD_TYPES[n − 1]` (same list in every world: 1 `classic`, 2–4 `meadow`, 5–7 `village`, 8–10 `river`, 11–13 `rooms`, 14–16 `arena`, 17–20 `maze`); `levelTier(world, n)` = position inside its block of one type (0…3). Each tier removes one bush (`bushCount`), never below `CFG.BUSH_MIN[type]`.
- **Seed**: `levelSeed(world, n)` = 1 for `n = 1` in every world (so every world's level 1 is the kids' drawing, Park level 1 = `tests/fixtures/level1.json`), else `(worldIndex + 1) × 100 + n`. The 3D decorations are seeded by the level number only (same `n` → same decorations in every world).
- **Current level**: `curWorld` + `level` (= n). `selectWorld(w)` (world card, ↑/↓, D-pad up/down via `cycleWorld(d)`) sets `curWorld`, saves `progress.lastWorld`, jumps to that world's `unlocked` level and calls `resetWorld`. `changeLevel(d)` clamps to 1…`worldProgress().unlocked`. `nextLevel()` after the last level → `toMenu()`. The old place picker (`PLACES`, `placeSel`, `cyclePlace`, `currentPlace`, key `bebebe-place`) is removed; `bebebe-place` is no longer read.
- **Difficulty** (logic section): **`difficulty(world, n, lost = 0)`** is the single source of the Big One's numbers → `{ chase, search, patrol, hearts, boost }`. `boost` = `levelBoost` (`CFG.WORLD_SPEED_START[w]` + `levelPos(n) × CFG.SPEED_PER_LEVEL`) + `floor(lost) × CFG.BIG_SPEED_PER_HIT` (uncapped); `chase` = `BIG_CHASE_SPEED + boost`, `search` = `BIG_CHASE_SPEED × 0.85 + boost`, `patrol` = `BIG_PATROL_SPEED + boost × 0.5`, each through `chaseCap` = `min(CFG.BIG_CHASE_MAX, v)`; `hearts` = `bigHearts` = `min(BIG_HP_MAX, BIG_HP + floor(levelPos / HP_LEVELS_PER_HEART) + w × HP_PER_WORLD)`. `CFG.BIG_CHASE_MAX` is a getter = `CHASE_MAX_SHARE × PLAYER_SPEED` (142.5) — derived; change `CHASE_MAX_SHARE`. `resetWorld` takes `big.maxHp` from `difficulty(curWorld, level).hearts`; `bigDifficulty()` = `difficulty(curWorld, level, big.maxHp − big.hp)`; `bigSpeeds()` → `{ chase, search, patrol }` used by `updateBig`; `bigBoost()` = its `boost`. The ×0.85 and ½ factors are literals (not `CFG`).
- **Menu and win screen**: `worldCard(w, x, y, cw, ch)` draws one card (`worldPicture` from `THEMES[w]` colours, name, `worldStars(worldStarsOf(w), STARS_PER_LEVEL × 20)`), pushes a button `world:<w>` → `selectWorld(w)` and a record into `worldCards` `{ world, x, y, w, h, name, stars, selected }` (reset each frame in `drawUI`). Desktop: four cards in a row under the rules, the level selector and type label under them; phone: 2×2 cards in the right column. The total ⭐ counter next to the coins stays. `winText()` sets `winLine` = `worldDone(worlds[w], w)` after the last level (Russian gender by key), else `winSub`. `endActions("win")` after level 20 returns Menu (green, also Enter / pad A) + Shop only; desktop then uses a two-button layout.

## Level types and the generator (SPEC-002)
- **`generateLevel(world, lv, attempt)`** (pure, theme-free, seeded only by `mulberry32(levelSeed(world, lv) * 7919 + attempt * 104729 + 13)`): builds the layout context `lc` (`lv, attempt, type, tier, rng, ri, items, occ, reserve, isFree, hWall, vWall, place(n, make, w, h, m, ok)`, `small`, `bigPt`, `doors`, `homes`, `meta`) → **`placeHomes(lc, variant)`** (Little Ones' house 7×6 top-left with `safe`, beds and spawns; the Big One's 6×6 house through `bigHouse()` bottom-left `"side"` or bottom-right `"diagonal"`; `CFG.DOOR_APRON` cells reserved in front of every door; `variant` = `"side"` for classic, `CFG.LAYOUT[type].homes` if set, else the seed) → **`LAYOUTS[type](lc)`** → mirror `fx`/`fy` (not on level 1; mirrors items, danger `exits`, `meta.areas` and the doors) → flowers. Returns `{ type, items, small, big, flowers, doors: { small, big }, meta }`; `doors` = door openings `{ x, y, w, h, dx, dy }` (outward direction) for the fairness rules; `meta` = layout facts (`deadEndsBefore/After` for the maze, `areas` — plazas, bridges, rooms + doors, arena block/ring/gaps — for tests, `bad` = the layout could not be built, `vertical` for the river).
- **Layouts** (all sizes in `CFG.LAYOUT[type]`): `classicLayout` = the old body, byte-for-byte (fixture `tests/fixtures/level1.json`); `meadowLayout` (ponds, trees, rocks, bushes); `mazeLayout` (3-cell modules: Kruskal perfect maze, home areas and 5×5 plazas opened, braided to ≤ `CFG.MAZE_DEAD_ENDS`, walls as `maze` cells); `villageLayout` (`floor` `square` + fountain `pond`, `cottage` blocks with `street` margin, bushes next to cottages); `riverLayout` (`water` pieces between the houses, bends, `floor` `bridge` with `across: "x"|"y"`, bushes split between banks); `roomsLayout` (diagonal only: two wings with BSP rooms, `build` walls, `tile` floor, outside doors into both yards); `arenaLayout` (diagonal only: `arena` block and ring with gaps, optional half-ring). `emitWalls(items, occ, wall, kind)` turns a wall-cell grid into wall rectangles.
- **Item kinds and flags** (`applyWorld` → `obstacles`): `wall` kinds `home`/`bighome`/`build`/**`maze`**/**`arena`** (and `hedge` from the fallback) — move + sight; **`cottage`** — rect, move + sight; **`water`** — rect, move only (sight passes); `pond` — move only, `fountain: true` for the village fountain; `tree`/`rock` — circles, both. `floor` kinds `wood`/`tile`/**`bridge`** (`across` kept)/**`square`** are walkable ground only. Bridges are gaps between water pieces, so they are free cells.
- **`buildGrids()`** rasterizes: each obstacle marks only the fine/coarse cells of its own bounding box (same rules as `covers()`), because a level may be built up to `CFG.LEVEL_ATTEMPTS` times; then `moveGridBig`/`blockedBig` add the safe zone.
- **`validateLevel(gen, type)`** (on the applied world) → `{ ok, fails, seen, freeRatio, bigReachAll, smallReachAll, housePath, doorClear, deadEnds: { count, longest, before }, bushes }`. Rules: `smallReach` (`connectivity()`), `bigReach` (`floodCells` on `blockedBig` from his spawn), `housePath` (A* on `blockedBig`, √2 diagonal, shortest big-door → cell-in-front-of-small-door pair, in `CFG.HOUSE_PATH`; skipped for `classic`), `free` (`CFG.FREE_MIN[type]`, outside both houses), `doors` (`CFG.DOOR_APRON` rows in front of every door free on both grids), `deadEnds` (`deadEndScan`: 2×2 free windows of `blockedBig` as nodes, leaves peeled; maze: count outside houses and aprons ≤ `floor(before × MAZE_DEAD_ENDS)`, others: `longest ≤ CFG.DEAD_END_MAX`), `bushes` (`CFG.BUSH_MIN`), plus `layout:<meta.bad>`.
- **`buildLevel(world, lv)`**: attempts 0…`LEVEL_ATTEMPTS - 1`, first `ok` wins. Fallback: rebuild the attempt with the lowest `failScore` (fail count, +100 if a reach rule failed), fill with `hedge` every free cell the Little Ones can't reach or (outside their house) the Big One can't reach, `console.warn`. Sets `reachable`; returns the report without `seen`/`ok`, plus `tier`, `attempt`, `attempts`, `fallback`, `rejects`, `ms`.
- **`loadLevel(world, lv)`** (from `resetWorld`, with `curWorld, level`): `levelCache` (`levelKey(world, lv)` → accepted attempt) rebuilds that attempt directly and re-validates it; a cached attempt that no longer passes (e.g. `CFG` changed) is dropped and the level is built from attempt 0. Fallback results are not cached. Sets **`levelInfo`** `{ world, lv, type, attempt, fallback, cached, ms }`. `clearLevelCache()` empties the cache.
- **`levelReport(world, lv)`** (tests): saves the world (`keep` = `obstacles, bushes, floors, decor, trees, flowers, safeZone, dangerZone, spawns, reachable` + copies of the five grids), runs `buildLevel`, restores everything in `finally`. The comment above `applyWorld` says it: new world state → add it to `keep` and to `__bb.worldState`.
- **Bots on new layouts**: `fleePoint` only picks `reachable` cells and falls back to `freePointNear`; `lurkPoint` snaps to `freePointNear(p)` (nearest free reachable cell via `freeCellNear`), so targets are never inside walls or across water.
- **3D** (`buildMap3D`): the place is the built level's world (`levelInfo.world`, else `curWorld`); `builtKey = mapKey()` = `levelInfo` `world:lv:attempt:fallback`, and `rebuild3D` rebuilds the map only when `mapKey()` changes. `cottage` → `makeCottage` (body, pitched roof along the long side, snow on winter roofs, door, windows); `water` → `makeWaterFor` (flat, no rim, so pieces join into one river; waves except winter) + `riverBanks` (one `InstancedMesh` of edge strips on water sides not next to water, a bridge or the map edge; stone edge in the schoolyard); fountain `pond` → `makeFountain` (bowl, water, column, bobbing drop in `waves`, `userData.baseY`); `maze` walls → boxes in `THEMES[place].maze` colours + `mazeDeco` (`InstancedMesh`: bumps, posts, snowballs, locker seams); `arena` walls via `walls.arena`. Maze walls keep `WALL_H` 0.85 (characters stay visible). `paintGround` draws `bridge` planks (across the crossing) and `square` cobbles. `tag(mesh, piece)` sets `userData.piece` for `__bb.mapPieces()`; `disposeTree` also disposes `InstancedMesh` buffers.
- **Theme keys** (`THEMES[place]`): `walls.arena` `[wall, top]`; `maze` `{ wall, cap, deco: "bumps"|"posts"|"snow"|"seams", decoC }`; `cottage` `{ wall, roof, door, window, snow? }`; `water` `{ c, edge, stone?, waves, wave }`; `bridge` `[plank, gap]`; `square` `[base, stone]`; `fountain` (bowl colour).
- **Banner and menu label**: `startGame` → `showBanner()` sets `banner = { text: levelIntro(worlds[curWorld], level, types[type]), t }` ("Park · Level 17: Maze") unless the last banner was under `CFG.BANNER_REPEAT` s ago; `updateFx` advances `banner.t` and clears it at `CFG.BANNER_TIME`; `bannerAlpha()` fades over `CFG.BANNER_FADE`; `drawBanner()` (only in `play`) draws the plate under the top bar, adds no buttons. The menu draws `types[levelType(curWorld, level)]` next to the level selector (desktop: right of it; phone: above it) and stores its box in `typeLabel` `{ text, x, y, w, h, size, rulesBottom }` (`rulesBottom` = bottom of the world cards).
- **Test fixtures**: `tests/fixtures/level1.json` (items and spawns of `generateLevel("park", 1, 0)`; every world's level 1 must match it exactly), `tests/fixtures/levels-worlds.json` (per `levelKey` for all 80 levels: type, accepted attempt, FNV hash of the generated JSON — regenerate only on purpose, saying why in the commit; replaces `levels-2-61.json`). Tests that change `__bb.CFG` restore it and call `__bb.clearLevelCache()`.

## The Big One's house (SPEC-003)
- **`bigHouse(items, x0, y0, doors)`** (generator section) emits everything of the 6×6 house: `bighome` walls with 2-cell doors (`doors: [{ side: "top"|"bottom"|"left"|"right", at }]`), the dark floor, the bed, and the danger item `{ t: "danger", x, y, w, h, exits }` = the floor; `exits` are 2-cell spots `CFG.DANGER_EXIT` cells outside each door. The mirror step in `generateLevel` mirrors `exits` too. Level 1: doors top and right, same layout as before. `placeHomes` (SPEC-002) builds the Big One's house through `bigHouse()` on every level type, so every type has the danger zone.
- `applyWorld` turns the item into **`dangerZone`** `{ x, y, w, h, exits: [{x, y}] }` (pixels; exits are the spot centres); `inDanger(p)` / `inDangerXY(x, y)` test it. `reachable` (from `connectivity()` in `loadLevel`) marks the cells the Little Ones can reach from their house.
- `updateDanger(dt)`: a Little One in state `ok` inside the zone gets `dangerT += dt` (paused while `hugAnim` > 0, reset to 0 outside or in any other state); at `CFG.DANGER_TIME` → `throwOut(l)`: placed at `nearestExit(l)` (or `freeCellNear` it: not blocked, reachable, not in the zone), `dizzy = CFG.DIZZY_TIME`, pop text `thrownOut`, `SFX.thrown`.
- Bots: `steerTo` adds `CFG.BOT_DANGER_COST` per danger cell to their A* cost (not for the Big One); `fleePoint` and `lurkPoint` never pick a point in the zone; a bot with `dangerT > CFG.BOT_DANGER_LEAVE` gets task `leave` and walks to `nearestExit`.

## Bonus stars (SPEC-003)
- `bonusStars` (`{ id, x, y, t, life }`), separate from `items`; `starCd` counts down `CFG.STAR_EVERY`, at most `CFG.STAR_MAX`, each lives `CFG.STAR_LIFE` and blinks for the last `CFG.STAR_BLINK` (in `syncStars`).
- `starSpotOk(cx, cy)`: not blocked, `reachable`, not in `safeZone`/`dangerZone` nor within `CFG.STAR_HOUSE_MARGIN` cells of the Big One's floor, at least `CFG.STAR_MIN_FROM_HOME` cells (straight line) from the safe house walls, no item or star on the cell. `spawnStar(x?, y?)` picks a random good cell (or the given point, for tests).
- `updateStars`: a `player` with `canAct` within `r + CFG.STAR_PICK` takes it: `stats.starCoins` and `progress.coins` += `CFG.STAR_COINS` at once (saved), pop text, burst, `SFX.star`. `giveReward` reports them as `lastReward.starCoins` (and inside `lastReward.coins`), on top of the `COINS_MIN_WIN` floor; the win and lose screens show them as a separate line.

## Names (SPEC-003)
- Slots `p1`, `p2`, `big`, `bot1`..`bot4`. `namesTyped` holds only what a kid typed (`""` = language default); `nameFor(slot)` = typed or `defaultName(slot)` (`player1`/`player2`, `defaultBig`, `defaultBots[i]` of the current language). `cleanName`: control characters removed, trimmed, at most `CFG.NAME_MAX` code points. `nameOf(l)` maps a character to its slot (bots by `botIndex`). Names are drawn only with `fillText`.
- **Name input overlay**: `nameLabel(rect, slot, color)` draws a label button with ✏️ and registers it with `onUp: true`; such buttons fire on **`pointerup`** of the same pointer (`pendingUp`), because iOS Safari opens the keyboard only for a focus inside a pointerup/click. `openNameInput(rect, slot)` puts an HTML `<input class="name-input">` exactly over the rect (`placeNameInput`, from `CSS_W / UW`, font ≥ `CFG.PHONE_TEXT.input` = 16 px, `enterkeyhint="done"`, `autocapitalize="words"`); Enter, blur or a tap on the canvas saves, Escape cancels; saving an unchanged name keeps the default. While `nameInput` is open, `keydown` and gamepad buttons are ignored; `drawUI` closes it when the mode is no longer `skins`/`names`.
- In play: `drawMarkers` draws names above heads (40 % alpha in a bush) and the Big One's name above him; `drawHUD` starts the hearts bar with his name (`labelFit` shrinks or cuts long names; hearts get denser above 8).

## Air kisses (SPEC-004)
- **Shop and stock**: `KISSES = { price, pack }`; `buyKisses()` takes `KISSES.price` coins and adds `KISSES.pack` to `progress.inv.kisses` (one pool for both players); not enough coins → `SFX.out`. The shop draws three cards from one list (mittens, mega, kisses; button ids `buy:<kind>`), card text by `fitText`/`wrapText`; texts `kisses`, `kissDesc`, `kissPack(n)`, `kissHave(n)` (ru uses `ruPlural`), pop texts `kissHit`, `noKissHome`, `blush`.
- **Throw**: `throwKiss(pi)` works only in `play`, without `pendingWin`, for a `player` with `canAct` and `inv.kisses > 0`. In `safeZone` → pop text `noKissHome`, nothing spent. Then `kissCd` must be 0: one kiss is spent (saved), `l.kissCd = CFG.KISS_COOLDOWN` (counted down in `update`), and a kiss `{ id, owner, x, y, dx, dy, travel }` starts at the player's front along `l.dir`. Inputs: `onKey` → `kissKeyPlayer(code)` (one player: `KeyE`/`Space` → 0; two players: `KeyE` → 0, `Enter`/`NumpadEnter` → 1); gamepad button `CFG.PAD_KISS` (2 = X / □) in `onPadButton(b, pad)` (with two players pad i throws for player i); touch `kissButton(pi)`.
- **Flight**: `updateKisses(dt)` (called in `update` after `updateHugAnim`) moves each kiss in steps of `CFG.KISS_STEP` at `CFG.KISS_SPEED`, up to `CFG.KISS_RANGE`. Each step checks, in this order: `seeSolidAt` (the sight grid: every wall kind, trees, rocks, cottages, the map edge → puff, done; ponds, water, bushes pass); the hit `dist < big.r + CFG.KISS_HIT_PAD` **and** `los(kiss, big, seeSolidAt)` (never through a wall); the end of the range. Sight-blocking walls added by SPEC-002 stop kisses automatically through the same grid.
- **Hit**: `kissHit(k)` always bursts hearts; no damage while `big.stun`, `big.hugCd` (the 0.3 s after the shock) or `big.blush` > 0. Otherwise `big.hp -= CFG.KISS_DAMAGE` (floor 0), `big.blush = CFG.KISS_BLUSH`, `big.blushBy = k.owner`, `pushCd` cleared, pop texts `kissHit` + `blush`, `SFX.mwah`; `hp` 0 → `winSoon()` (the same path as the last hug: `pendingWin`, rewards, stars).
- **Touch button**: `kissBtnRect(pi)` (size `CFG.KISS_BTN`; bottom right, or bottom left for P1 with two players). `drawHUD` calls `kissButton(pi)` only on touch, in `play`, with `inv.kisses > 0`; it pushes `{ id: "kiss:<pi>" }` into `buttons[]`. `pointerdown` hit-tests `buttons[]` before it starts a stick, so a touch on the button never starts a joystick. Grey when not `canAct`, in the house or during `kissCd` (cooldown arc). Without touch the HUD shows `💋 ×N` next to the mittens.
- **3D**: `syncKisses` keeps one mesh per kiss in `kissGroup` (`kissMeshes` by id): an extruded pink heart at `KISS_Y` (chest height) with a sparkle trail; `rebuild3D` clears them. The Big One's blush (`syncBig`): `headMat.emissive` red, `cheeks` visible, head tilted up, hands together; 💗 label in `drawMarkers`; pale cone in `updateCone`.

## Half hearts (SPEC-004)
- `big.hp` holds 0.5 steps (hug power is whole, kiss damage 0.5, both exact in floating point).
- `heartFill(i, hp)` = `clamp(hp - i, 0, 1)` (1 full, 0.5 half, 0 empty); `drawHpHeart(x, y, s, f)` draws a half as left red / right grey. `drawHUD` uses both for the hearts bar.
- Only whole hearts lost speed him up: `difficulty(…, lost)` adds `Math.floor(lost) * CFG.BIG_SPEED_PER_HIT`; `bigBoost()` returns that boost, `updateBig` uses the capped `bigSpeeds()`.
- `fmtHearts(n)`: 2.5 → `2½`, 0.5 → `½`, 0 → `0`; the lose screen passes it to `loseSub`.

## Phone mode (SPEC-005)
- **Detection**: `isPhone()` (screen section) = `?phone=1` → true, `?phone=0` → false, else `isTouch && min(screen.width, screen.height) <= CFG.PHONE_MAX_SHORT_SIDE`. Computed once into **`PHONE`** (like `STANDALONE`); `PHONE` adds `body.phone` (CSS: `#wrap` without rounded corners and shadow). With `PHONE` false every code path is the desktop one.
- **World vs UI space** (the rule): `W`/`H` = the world, always 960×640 (map 30×20 × `CELL`). `UW`/`UH` = the UI layer's logical size: on desktop `UW = W`, `UH = H`; on a phone `UH = CFG.PHONE_UI_H` (420) and `UW = UH × CSS_W / CSS_H` (unrounded). Every UI drawing, hit-test and `toScreen` result is in UI px; world logic uses `W`/`H`. `toGame(e)` maps pointers into UI px; `VIEW` = canvas px per UI px.
- **`fit()`**: desktop letterboxes `W × H` into `playArea()`; a phone fills `playArea()` (no bars). Then the **`onFit`** hook (set in the 3D section, phone only): camera aspect = canvas shape, `fitCamera()` again (full-map distance `cam.dFull`), visible-ground trapezoid (`groundCorners` → `camOff`), follow distance `cam.dFollow` = `CFG.PHONE_VIEW_ROWS` rows tall, `camProbe` for `uiOf`, the shadow box. On a phone an open name input stays open on a height-only resize (the on-screen keyboard) and closes (name kept) only when the CSS width changes (the phone was rotated); `drawUI` refreshes its rect every frame from the `name:<slot>` button and calls `placeNameInput()`.
- **Sizes in CSS px**: `cpx(n)` = n CSS px in UI px; `minPx(cat)` = the smallest text of a kind (`CFG.PHONE_TEXT`: `title` 24, `main` 15, `hint` 13, `input` 16). `fz(size, cat)` returns `size` on desktop, on a phone at least `minPx(cat)`, and records it. `textSizes` = the smallest size drawn this frame per kind (+ `drawn` from `label`/`fitText`), reset in `drawUI`; tests read it.
- **Camera** (3D section, «Камера телефона»): `cam = { x, y, lax, lay, zoom, dFollow, dFull, full }`. `cam.zoom` 0 = follow the hero, 1 = whole map; it goes to 1 outside `play`/`pause` (menu, skins, shop, win) and back to 0 in play over `CFG.CAM_ZOOM_TIME` (smoothstep). **`updateCamera(dt)`** is called from `frame()` after the logic, **not** from `update` (the tests' `step()` does not move the camera; they call `__bb.updateCamera`). It eases the look-ahead (`CFG.CAM_LOOKAHEAD`, `CAM_LOOKAHEAD_RATE`; only while the hero walks in state `ok`, not hugging) and the target (`CFG.CAM_FOLLOW`, frame-rate independent `1 − e^(−k·dt)`), then `applyCamera()`. **`camSnap()`** (from `startGame`) puts the camera on the hero at once, zoom 0. `camHero()` = the first `player`. Desktop: `updateCamera`/`camSnap` return at once; the camera stays at `camBase`.
- **`followGoal(l, x, y)`**: `clampLook` keeps the visible ground at most `CFG.CAM_EDGE` cells past the map edge. Then (while the mini-map shows) 3 passes check the hero's feet and his name height (`CFG.CAM_HERO_H`) with `uiOf`, and each correction is continuous (no jumps of the goal): near the left/right screen edge (`CFG.CAM_HERO_SIDE`) the camera shifts sideways; under the top bar (+ `CAM_HERO_PAD`) it shifts down; under the mini-map + team chips corner it shifts **down first**, eased in over the strip `CFG.CAM_HERO_RAMP` (120 CSS px) left of that corner as the hero approaches, and only once down is capped by the map edge it shifts **sideways**, eased in by how much down was missing. The extra overshoot is `CAM_EDGE_MAX − CAM_EDGE`, so the total beyond the map edge is at most `CFG.CAM_EDGE_MAX` (4 cells) in all. In the very top-right corner (both limits reached) the hero's name may sit under the team chips. `phoneOccluders()` is now used only by the edge arrows (its `ways` and `sides` are unused); the camera computes its own limits from `phoneTopBar()`, `minimapRect()`, `teamRect()`.
- **Shadows**: on a phone only, `applyCamera` moves the sun with the look point and narrows the shadow camera to `shadowBox` (visible ground at heights 0…`CAM_SHADOW_H`, in light space, + `CAM_SHADOW_PAD`), snapped to shadow texels per axis (no shimmer); it blends to the full-map box `SHADOW_FULL` as `zoom` → 1. Fog unchanged. Camera shake is scaled by `camDist / cam.dFull`. `frame()` clamps `dt` to ≥ 0 (a negative first-frame dt shook the camera).
- **Vision cone shared**: `visionPoly(n, out)` (movement section) = the Big One's wall-clipped view polygon in world px; `bigCalm()` = stun / noPush / blush. `updateCone` (3D) fills `coneBuf` with it every frame; `drawMinimap` draws the same-frame `coneBuf` (no second ray march).
- **Mini-map** (only when `showMinimap()` = phone and `play`/`pause`): `minimapRect()` top-right, width `UW × CFG.MINIMAP_W`, 3:2, margin `CFG.MINIMAP_MARGIN`. **`minimapBase(r)`** draws ground, floors, safe/danger zones, obstacles (walls darkened by `mixHex`) and bushes into an offscreen canvas, in `THEMES[levelInfo.world]` colours, cached by the key `levelInfo.world : lv : attempt : fallback : r.w : VIEW` (`mmDraws` counts redraws; restarting the same level redraws nothing). **`drawMinimap(t)`** each frame: base, cone, stars, items, bots / downed (blinking) / the Big One / the hero, the camera frame from `camRect()`; every marker goes through `mark(kind, x, y)` into `mmState.markers` (reused objects, `mmCount` this frame).
- **Edge arrows**: `drawEdgeArrows()` (play only) for the Big One and every downed Little One that is off screen or under `phoneOccluders()`; the arrow sits where the hero → target line meets the screen edge; if that spot is blocked (mini-map, `buttons`, `hudRects`, another arrow) it walks along the perimeter both ways to the nearest free spot. Results in `edgeArrows` `{ kind, x, y, angle, r }`.
- **Phone HUD**: `drawHUD` → **`drawHUDPhone(t)`**: top bar (Big One name + hearts plate, timer plate, pause, fullscreen unless `STANDALONE`), team chips in **`teamRect()`** under the mini-map, the 💋 button bottom-right (`kissBtnRect`, `CFG.PHONE_KISS_BTN`) with the mittens plate next to it, touch hint and rest bars at the bottom left of those buttons, then mini-map and arrows. Plates are recorded in `hudRects` `{ id, x, y, w, h }`. `phoneTopBar()` / `teamRect()` / `phoneOccluders()` are shared by the HUD, the camera and the arrows. Banner on a phone: a plate under the top bar, left of the mini-map (`bannerRect`).
- **Phone screens**: `drawOverlay` → **`drawOverlayPhone()`** for menu (two columns), skins (`phoneSkinCols()`: Player 1 + the Big One), names, shop, pause, win/lose; helpers `pLabel`/`pText`/`pWrap`/`pButton` (text shrinks to fit but never below its `PHONE_TEXT` kind) and `phoneFrame`. Content shared with desktop: **`shopCards()`** (the three shop cards), **`endActions(m)`** (win/lose buttons), **`chipText`**, **`timerText`**, **`restText`**. The rotate overlay on a phone wraps `rotate` in title size and clears `buttons`.
- **One player**: `resetWorld(n)` forces `n = 1` on a phone, so `startGame(2)`, key `2` and the gamepad fall back to one player; the phone menu has no "2 players"; gamepad button 3 does not randomize P2's outfit.
- **Joystick**: on a phone a touch in play that is not on a button starts a stick only if `x ≤ UW × CFG.STICK_ZONE`; `stickR()` = `CFG.PHONE_STICK_R` CSS px in UI px (desktop: `STICK_R` 55); the base follows the finger beyond `1.6 × stickR()`.
- `addButton` returns the button and keeps `text` and `textW` (tests check that labels fit); on a phone it records the label size as `main`.
- **Tests**: `tests/phone.spec.js` — phone tests open `openGame(page, { query: "?phone=1" })` at 844×390 with `hasTouch` + `isMobile` (sizes tests also 667×375 and 932×430); the "desktop unchanged" test compares the camera and `toScreen` of fixed points with values captured on master.

## States
- **Game `mode`**: `menu` · `skins` · `names` (bot names, opened by "👥 Friends" on the skins screen) · `shop` · `play` · `pause` · `win` (· `lose` — screen still exists but is not reached since "no game over").
- **Little One `state`**: `ok` → `down` (pushed; `downTimer` = `CFG.DOWN_TIME`) → rescued (`rescue` reaches `CFG.RESCUE_TIME` while a helper stands next to him, drains at `CFG.RESCUE_DRAIN` otherwise, reset to 0 when the helper is pushed) → `ok` (`invuln`) | not rescued → `home` (limps to `restSpot` = its spawn in the house) → `rest` (`restTimer` = `CFG.REST_TIME`) → `ok`. Extra: `hugAnim` > 0 while riding the Big One's shoulders; `fx.boots/cloak/shield` timers; `dangerT` (seconds in the Big One's house); `dizzy` (after being thrown out: can't move or hug, the Big One ignores him); `botWait` (set on a fall from `CFG.BOT_RESCUE_DELAY`; bots ignore the downed one until it is 0). **`canAct(l)`** = `ok`, no `hugAnim`, no `dizzy` — used for moving, hugging, contacts, picking stars, throwing kisses. `kissCd` (SPEC-004): seconds until this player can throw the next air kiss.
- **Big One**: `state` `look` / `patrol` / `chase` / `search`; overlays `stun` (after a hug, can't move/push, no new hug), `slip` (banana: lying, can be hugged from any side), `pushCd` (stands after a push), `noPush` (rest after a push: sees nobody), `blush` / `blushBy` (SPEC-004, after an air kiss: seconds left and the thrower's player index). While `blush` > 0 he doesn't move, turn or push, bots don't flee and the cone is pale, but he **can be hugged** (`hug` sets `blush = 0`, then the usual `stun`). `blush` also counts down while he lies after a banana (`slip`). When it reaches 0 with no `slip`/`stun`: `state = "chase"`, `lastSeen` = the thrower's position, `dir` turned to the thrower at once; if it ends during `slip`, the slip end sends him to `look` as usual.
- **Bots**: `task` `rescue` / `flee` / `attack` / `lurk` / `leave` (walking out of the Big One's house); one attacker at a time (`attackToken`, `botAttackCd`).

## PWA (SPEC-001)
- **Site files** (all that GitHub Pages publishes): `index.html`, `manifest.webmanifest`, `sw.js`, `icons/` (`icon.svg` source → PNGs by `scripts/make-icons.js` / `npm run icons`), `v1-2d/`. Workflow `.github/workflows/pages.yml`: job `test` (whole Playwright suite) → job `deploy`.

Hides the HUD fullscreen button (`drawHUD`) and the install hint. `isIOS` + `showInstallHint()` → one menu line `I18N.installHint` under the controls text (`drawOverlay`, menu).

## Save data (localStorage)
- `bebebe-progress` (SPEC-006): `{ worlds: { park|school|beach|winter: { unlocked: 1..20, stars: { [n]: 1..3 } } }, lastWorld, coins, inv: {mittens, mega, kisses}, equip: [p1, p2] }`. Defaults come from `freshProgress()` (every world `freshWorld()` = `{ unlocked: 1, stars: {} }`; also used by `resetProgress`, which keeps `lastWorld` = the shown world). **`loadProgress(pv)`** never throws: each world goes through `cleanWorld` (broken → default, `unlocked` clamped to 1…20, stars only for n 1…20, capped at `CFG.STARS_PER_LEVEL`); unknown `lastWorld` → `park`; `inv` merged with defaults and `inv.kisses` forced to a whole number ≥ 0. **Migration**: a save with the old flat `unlocked`/`stars` (`hasFlatProgress`) moves them into the Park (`unlocked` → min(20, old), stars for n ≤ 20, higher levels dropped); if it also has `worlds` (an old tab wrote the flat fields back), they merge into the Park — the larger `unlocked`, the best stars per level. The flat fields are left out of the result, and a migrated save is written back once on load. Coins, inventory, equip and names are untouched. `giveReward` writes stars/`unlocked` only into `worldProgress()` (the current world) and sets `lastWorld`; coins = `COINS_WIN + n × COINS_PER_LEVEL + w × COINS_PER_WORLD` + bonuses − penalty (floor `COINS_MIN_WIN`), fast time `FAST_TIME(n) + w × FAST_PER_WORLD`; `lastReward` adds `world`, `level`, `worldDone` (n = 20).
- `bebebe-outfits`: `{ p1: {hair, hat, jacket, pants}, p2: {...}, big }`. `bebebe-place`: no longer read (SPEC-006: the place is the world); old saves may still have it. `bebebe-lang`: `en|es|ru`.
- `bebebe-names` (SPEC-003): `{ p1, p2, big, bots: [b1, b2, b3, b4] }` — only typed names, `""` = language default; every field cleaned on load, missing or broken data → defaults.
