# Architecture — bebebe-game v2 (3D)

One `index.html` (+ PWA files, see below): a small non-module script (offline hint) and one `<script type="module">` that imports Three.js r187 from jsDelivr. Two stacked canvases inside `#wrap`: `#gl` (WebGL, Three.js) below, `#game` (2D, UI and input) on top.

## Layers (keep them apart)
1. **Logic** — world, level generator (pure: no Three.js, no theme; the world only picks the seed), pathfinding, rules, bots, the Big One, items, progress. Works in "logic pixels": 960×640, `CELL = 32` (1 cell = 1 unit in 3D). Knows nothing about Three.js.
2. **3D** — builds meshes from the world (`buildMap3D`, `buildCharacters`) and copies state into them every frame (`syncScene` → `syncLittle`, `syncBig`, `syncItems`, `syncStars`, `syncKisses`, `updateCone`). Only reads game state.
3. **2D UI** — menu screens (home, level map + level card, story, shop with the Wardrobe tab; SPEC-017), HUD, name tags, timers, mini-map; positions of world things via `toScreen(x, y, heightPx)`. Buttons are registered each frame in `buttons[]` and hit-tested on `pointerdown` (on the map and the story chapters: on `pointerup`, see Screens and menus). Draws in **UI space** `UW × UH` (see Phone mode), never in world `W × H`.

## Worlds and level keys (SPEC-006, SPEC-016)
- **A level is `(world, n)`**: SPEC-016 world lists (all `Object.freeze`d): **`MAIN_WORLDS`** = `["park", "field", "city", "school"]`, **`BONUS_WORLDS`** = `["beach", "winter"]`, **`WORLDS`** = `[...MAIN_WORLDS, ...BONUS_WORLDS]` (story order = menu order; the world is also the level's place, `THEMES[world]`), `n` = 1…`levelsPerWorld()` = `CFG.WORLD_TYPES.length` (20). `levelPos(n)` = clamped `n − 1`. **`levelKey(world, n)`** = `"world:n"` keys `levelCache` and the fixtures.
- **Three ways to use a world** (SPEC-016) — never mix them:
  - **by name**: seeds (`WORLD_SEED`), `levelCache`/`levelKey`, `levelReport`, `levelInfo.world`, `progress.worlds[w]`, `progress.lastWorld`, `THEMES[w]`, `I18N.*.worlds[w]`, balance report rows, `CFG.BALANCE` entries;
  - **by difficulty index** **`worldDifficulty(world)`** = `CFG.WORLD_DIFFICULTY[world] ?? 0` (park 0, field 1, city 2, school 3, beach 3, winter 4): `levelBoost`, `bigHearts` (→ `difficulty()`), `rewardBase`, `fastTarget`;
  - **by story position** `worldIndex(world)` (position in `WORLDS`, unknown → 0): only `cycleWorld`, the order of the map tabs and of `STORY`, `CFG.BALANCE.ECONOMY.UPGRADE_WORLDS` (the first three = Park, Field, City) and the balance report's last world (`worlds.at(-1)` = Winter).
- **Bonus lock** (progress section; `p` = a progress object, default the live `progress`; a missing world or field counts as not won / no progress, never throws): **`bonusUnlocked(p)`** = every `won[1…20]` is `true` in every `MAIN_WORLDS` world; `worldHasProgress(w, p)` = `unlocked > 1` or any `won`/`stars` key; **`bonusOpen(world, p)`** = a main world, or `bonusUnlocked(p)`, or `worldHasProgress(world, p)`. Enforced in: `loadProgress` (a locked `lastWorld` → `WORLDS[0]`), `selectWorld` (ignores a locked world), `cycleWorld(d)` (walks round the list in direction `d`, skipping locked worlds), `resetProgress` (on a bonus world → back to `WORLDS[0]`), the map tab (`locked`, `tapWorldTab`), `mapStartWorld`, `chapterOpen` (bonus chapters). **Intentionally unrestricted**: `__bb.world` (setter) and `__bb.setProgress` — tests and `npm run balance` set any world directly. `giveReward(true)` reads `bonusUnlocked()` before and after writing the win: **`lastReward.bonusUnlocked`** is `true` only for the win that opened the bonus worlds (the one-time message; no save field).
- **Type and tier**: `levelType(world, n)` = `CFG.WORLD_TYPES[n − 1]` (same list in every world: 1 `classic`, 2–4 `meadow`, 5–7 `village`, 8–10 `river`, 11–13 `rooms`, 14–16 `arena`, 17–20 `maze`); `levelTier(world, n)` = position inside its block of one type (0…3). The ×0.85 and ½ factors are literals (not `CFG`).

## Level types and the generator (SPEC-002)
- **`generateLevel(world, lv, attempt)`** (pure, theme-free, seeded only by `mulberry32(levelSeed(world, lv) * 7919 + attempt * 104729 + 13)`): builds the layout context `lc` (`lv, attempt, type, tier, rng, ri, items, occ, reserve, isFree, hWall, vWall, place(n, make, w, h, m, ok)`, `small`, `bigPt`, `doors`, `homes`, `meta`) → **`placeHomes(lc, variant)`** (Little Ones' house 7×6 top-left with `safe`, beds and spawns; the Big One's 6×6 house through `bigHouse()` bottom-left `"side"` or bottom-right `"diagonal"`; `CFG.DOOR_APRON` cells reserved in front of every door; `variant` = `"side"` for classic, `CFG.LAYOUT[type].homes` if set, else the seed) → **`LAYOUTS[type](lc)`** → mirror `fx`/`fy` (not on level 1; mirrors items, danger `exits`, `meta.areas` and the doors) → flowers. Returns `{ type, items, small, big, flowers, doors: { small, big }, meta }`; `doors` = door openings `{ x, y, w, h, dx, dy }` (outward direction) for the fairness rules; `meta` = layout facts (`deadEndsBefore/After` for the maze, `areas` — plazas, bridges, rooms + doors, arena block/ring/gaps — for tests, `bad` = the layout could not be built, `vertical` for the river).
- **Layouts** (all sizes in `CFG.LAYOUT[type]`): `classicLayout` = the old body, byte-for-byte (fixture `tests/fixtures/level1.json`); `meadowLayout` (ponds, trees, rocks, bushes); `mazeLayout` (3-cell modules: Kruskal perfect maze, home areas and 5×5 plazas opened, braided to ≤ `CFG.MAZE_DEAD_ENDS`, walls as `maze` cells); `villageLayout` (`floor` `square` + fountain `pond`, `cottage` blocks with `street` margin, bushes next to cottages); `riverLayout` (`water` pieces between the houses, bends, `floor` `bridge` with `across: "x"|"y"`, bushes split between banks); `roomsLayout` (diagonal only: two wings with BSP rooms, `build` walls, `tile` floor, outside doors into both yards); `arenaLayout` (diagonal only: `arena` block and ring with gaps, optional half-ring). `emitWalls(items, occ, wall, kind)` turns a wall-cell grid into wall rectangles.
- **Item kinds and flags** (`applyWorld` → `obstacles`): `wall` kinds `home`/`bighome`/`build`/**`maze`**/**`arena`** (and `hedge` from the fallback) — move + sight; **`cottage`** — rect, move + sight; **`water`** — rect, move only (sight passes); `pond` — move only, `fountain: true` for the village fountain; `tree`/`rock` — circles, both. `floor` kinds `wood`/`tile`/**`bridge`** (`across` kept)/**`square`** are walkable ground only. Bridges are gaps between water pieces, so they are free cells.
- **`buildGrids()`** rasterizes: each obstacle marks only the fine/coarse cells of its own bounding box (same rules as `covers()`), because a level may be built up to `CFG.LEVEL_ATTEMPTS` times; then `moveGridBig`/`blockedBig` add the safe zone.
- **`validateLevel(gen, type)`** (on the applied world) → `{ ok, fails, seen, freeRatio, bigReachAll, smallReachAll, housePath, doorClear, deadEnds: { count, longest, before }, bushes }`. Rules: `smallReach` (`connectivity()`), `bigReach` (`floodCells` on `blockedBig` from his spawn), `housePath` (A* on `blockedBig`, √2 diagonal, shortest big-door → cell-in-front-of-small-door pair, in `CFG.HOUSE_PATH`; skipped for `classic`), `free` (`CFG.FREE_MIN[type]`, outside both houses), `doors` (`CFG.DOOR_APRON` rows in front of every door free on both grids), `deadEnds` (`deadEndScan`: 2×2 free windows of `blockedBig` as nodes, leaves peeled; maze: count outside houses and aprons ≤ `floor(before × MAZE_DEAD_ENDS)`, others: `longest ≤ CFG.DEAD_END_MAX`), `bushes` (`CFG.BUSH_MIN`), plus `layout:<meta.bad>`.
- **`buildLevel(world, lv)`**: attempts 0…`LEVEL_ATTEMPTS - 1`, first `ok` wins. Fallback: rebuild the attempt with the lowest `failScore` (fail count, +100 if a reach rule failed), fill with `hedge` every free cell the Little Ones can't reach or (outside their house) the Big One can't reach, `console.warn`. Sets `reachable`; returns the report without `seen`/`ok`, plus `tier`, `attempt`, `attempts`, `fallback`, `rejects`, `ms`.
- **`loadLevel(world, lv)`** (from `resetWorld`, with `curWorld, level`): `levelCache` (`levelKey(world, lv)` → accepted attempt) rebuilds that attempt directly and re-validates it; a cached attempt that no longer passes (e.g. `CFG` changed) is dropped and the level is built from attempt 0. Fallback results are not cached. Sets **`levelInfo`** `{ world, lv, type, attempt, fallback, cached, ms }`. `clearLevelCache()` empties the cache.
- **`levelReport(world, lv)`** (tests): saves the world (`keep` = `obstacles, bushes, floors, decor, trees, flowers, safeZone, dangerZone, spawns, reachable` + copies of the five grids), runs `buildLevel`, restores everything in `finally`. The comment above `applyWorld` says it: new world state → add it to `keep` and to `__bb.worldState`.
- **Bots on new layouts**: `fleePoint` only picks `reachable` cells and falls back to `freePointNear`; `lurkPoint` snaps to `freePointNear(p)` (nearest free reachable cell via `freeCellNear`), so targets are never inside walls or across water.
- **3D** (`buildMap3D`): the place is the built level's world (`levelInfo.world`, else `curWorld`); `builtKey = mapKey()` = `levelInfo` `world:lv:attempt:fallback`, and `rebuild3D` rebuilds the map only when `mapKey()` changes. `cottage` → `makeCottage` (body, pitched roof along the long side, snow on winter roofs, door, windows); `water` → `makeWaterFor` (flat, no rim, so pieces join into one river; waves except winter) + `riverBanks` (one `InstancedMesh` of edge strips on water sides not next to water, a bridge or the map edge; stone edge in the schoolyard); fountain `pond` → `makeFountain` (bowl, water, column, bobbing drop in `waves`, `userData.baseY`); `maze` walls → boxes in `THEMES[place].maze` colours + `mazeDeco` (`InstancedMesh`: bumps, posts, snowballs, locker seams); `arena` walls via `walls.arena`. Maze walls keep `WALL_H` 0.85 (characters stay visible). `paintGround` draws `bridge` planks (across the crossing) and `square` cobbles. `tag(mesh, piece)` sets `userData.piece` for `__bb.mapPieces()`; `disposeTree` also disposes `InstancedMesh` buffers.
- **Theme keys** (`THEMES[place]`): `walls.arena` `[wall, top]`; `maze` `{ wall, cap, deco: "bumps"|"posts"|"snow"|"seams"|"boards", decoC }`; `cottage` `{ wall, roof, door, window, snow? }`; `water` `{ c, edge, stone?, waves, wave }`; `bridge` `[plank, gap]`; `square` `[base, stone]`; `fountain` (bowl colour). SPEC-016 optional **`deco`** — colours of a place's details, one key = one meaning in any place (the key set is listed in the comment above `THEMES`): ground `chalk`, `asphalt`, `roadLine`, `zebra`, `kerb` (kerb and pool rim); fence `boards` (list, one per board in turn); goal `goal` (frame), `goalNet`, `goalArea` (patch under the goal, also the goal on the mini-map); `flag`, `flagPole`; "rocks" `cone`, `coneStripe`, `bag`, `bagStrap`, `cars` (list), `carGlass`, `carTyre`, `carLight`; "bushes" `hedge`, `hedgeLight`, `planter`, `soil`, `leaves`, `flowers` (list); outside the fence `lampPole`, `lampLight`, `mastPole`, `mastLight`, `benchSeat`, `benchLeg`, `hydrant`, `bin`, `ballSkin`, `ballPatch`. Code checks keys, not place names, where it can (`th.deco.boards` → ad boards instead of the fence, `th.deco.goal` → goals drawn in that colour on the mini-map).
- **Field and City** (SPEC-016; the generator stays theme-free — existing layout items are dressed per place): Field — `paintGround` → **`paintPitch(th)`** (mown stripes in `g2` every 4 columns, chalk outline, halfway line, centre circle, penalty and goal boxes, penalty arcs, corner arcs; drawn instead of the checkerboard, no flowers); `adBoards(D)` (one `InstancedMesh` of boards round the map, colour per board from `deco.boards`) instead of the post-and-rail fence; `makePondFor("field")` → **`makeGoal(place, o)`** (a goal on the pond's rect: green patch, transparent net box from `goalNetMat(color)` — one cached `MeshBasicMaterial` per colour in `netMats`, never disposed with the map — posts and crossbar on the side facing the map centre; the pond stays move-only, sight passes); `makeRockFor("field")` = cones + a kit bag; `makeBushFor("field")` = a round trimmed bush; maze `deco: "boards"` = coloured boards on the hedge (`mazeDeco`, colour per board from `deco.boards`); outside the fence light masts in the corners, corner flags, benches and balls (`makeStreetThing`). - **Banner**: `startGame` → `showBanner()` sets `banner = { text: levelIntro(worlds[curWorld], level, types[type]), short: levelIntroShort(…), t, place }` ("Park · Level 17: Maze") unless the last banner was under `CFG.BANNER_REPEAT` s ago; `updateFx` advances `banner.t` and clears it at `CFG.BANNER_TIME`; `bannerAlpha()` fades over `CFG.BANNER_FADE`; `drawBanner()` (only in `play`) draws the plate under the top bar, adds no buttons. The level type is shown on the level card (SPEC-017); the menu type label `typeLabel` is gone.
- **Test fixtures**: `tests/fixtures/level1.json` (items and spawns of `generateLevel("park", 1, 0)`; every world's level 1, all six, must match it exactly), `tests/fixtures/levels-worlds.json` (per `levelKey` for the 80 levels of Park, School, Beach, Winter: type, accepted attempt, FNV hash of the generated JSON — unchanged by SPEC-016; regenerate only on purpose, saying why in the commit), SPEC-016 `tests/fixtures/levels-field-city.json` (the same shape for the 40 Field and City levels). ## Randomness (SPEC-008)
- **Gameplay** randomness goes only through **`rng()`** (helpers section; a `mulberry32`, randomly seeded at start, so normal play is as before). `rand(a, b)` draws from `rng()`. Users: item and star spawns (`spawnItem`, `spawnStar`), `randomFreePoint`, the Big One's look timers and `lookSign`, bot timers (`botWait`, lurk, `botAttackCd`), `makeLittle`, `resetWorld`, `steerPoint`'s default repath delay. **`seedRandom(n)`** reseeds it (`seedRandom()` without a number → random again). Same seed + same inputs → the same game.
- **Visual** randomness uses **`vrand(a = 0, b = 1)`** on `Math.random`: `burst` particles, the hearts during the hug ride, camera shake in `syncScene`, snow in `buildMap3D`, `randomOutfit`. It never touches `rng()`, so sim mode (no particles) draws the same `rng()` sequence as normal play. The level generator and the 3D decorations keep their own seeded `mulberry32`.
- **Guard**: `noGameRng(name, fn)` sets `rngOff = name` while `fn` runs. It wraps `generateLevel` (→ `layoutLevel`), `rebuild3D` and the render half of `frame()`. A `rng()` call inside it: with **`strictRng`** on (tests: `openGame` sets `window.__bbStrictRng` by an init script, the game reads it at start) it throws `"<name>: gameplay rng() used; …"`; in normal play it falls back to `vrand()`, so the level still starts and the gameplay sequence is not consumed.
- `rngDraws` counts gameplay draws (a test checks that the autopilot's decision draws none).
- `tests/balance.spec.js` "same seed, same game" (`@fast`) also scans `index.html`: `Math.random` is allowed only in the `rngNext` seed and in `vrand`.

## Autopilot (SPEC-008)
- Logic section, before `updateBig`. Drives the **player** Little Ones for balance runs and tests; bots keep their own AI. It acts only like a player: **`autoMove[pi]`** = `{ x, y }` (length ≤ 1), which **`inputFor(l)`** adds like one more stick, and the buttons `throwKiss(pi)` / `useRescueKit(pi)` (only when `canUseKit`). It never writes the Big One's, the bots' or the Little Ones' state, `CFG` or `progress`, and draws no `rng()`.
- **`autopilot(on?, style?)`** → `{ on, style }`; style `"careful"` (default) or `"reckless"`; off clears `autoMove`. **`autoThink(dt)`** (called by `update` before `updatePlayers`; only in `play`) rebuilds `autoMove` every step.
- **`autoNavs`** (Map by player id → `{ x, y, r, path, repath }`, via `autoNav(l)`) is the autopilot's own path memory, so it never writes `l.path`. Paths come from **`steerPoint(e, gx, gy, dt, avoidCone, repathIn)`** — the target-point half of `steerTo` (A* with the bots' cone and danger costs), split out so the autopilot can use it with a fixed repath delay (`CFG.AUTOPILOT.repath`) instead of `rand()`. `steerTo` = `steerPoint` + the move. `resetWorld` resets `autoNavs` and `autoMove`.
- **careful** (`autoGoalCareful`): a slipped Big One → straight at him; else a downed friend no bot is closer to (unless the Big One is dangerous and near him); else a bonus star or a non-banana item within reach while he can't see it; else his back (`backPoint`) — from far along a path around his view, near and in front of him circling sideways. `bigDangerous()` = no stun, slip, blush, `pushCd` or `noPush`. Kit: when it can use one and has waited `kitWait` s unhelped (or is already limping/resting). Kiss: facing him, in range, line of sight, he can be blushed.
- **reckless** (`autoGoalReckless`): straight to his back, no hiding, no rescues, no buttons; always runs (SPEC-019).
- SPEC-019: **careful** tiptoes (`autoMove` length ≤ `TIPTOE_MULT`) while `autoTiptoe(l)` — see Tiptoe and hearing.
- All its distances and times are in **`CFG.AUTOPILOT`** (`repath`, `itemReach`, `pickSafe`, `rescueSafe`, `sneakNear`, `orbit`, `orbitStep`, `orbitR`, `arrive`, `backNear`, `backDist`, `hugIn`, `minStep`, `kitWait`, `kissAim`, `kissReach`).

## Tiptoe and hearing (SPEC-019)
- **Input → speed fraction**: `inputFor(l)` adds keys, gamepads and touch sticks into one vector; its length `t` (≤ 1) becomes the speed fraction `f`: `t < CFG.TIPTOE_MAX` → `TIPTOE_MULT × t / TIPTOE_MAX` (tiptoe, up to `TIPTOE_MULT`), else `t` (run). **`tiptoeKey(pi)`** caps `f` at `TIPTOE_MULT`: `TIPTOE_KEYS` = one player either Shift; two players P1 `ShiftLeft`, P2 `Slash` (the key left of Right Shift; "." on a Russian layout). Not Ctrl: with it P1's keys become browser shortcuts (Ctrl+W); Right Ctrl does nothing. `ShiftRight` stays P2's kit key (`kitKeyPlayer`). Keys alone give length 1 (run). The autopilot's `autoMove[pi]` is added after that, unchanged (its length already is the fraction). `updatePlayers` moves at `moveSpeed(l) × m` and stores **`l.speedFrac`** = `m` (0 when not moving); `updateBots` stores the fraction it steered with.
- **`isRunning(l)`** = state `ok`, `moving`, `speedFrac ≥ TIPTOE_MAX`. Tiptoe gives at most `TIPTOE_MULT`, which must stay below `TIPTOE_MAX` (`tests/invariants.spec.js` also checks `TIPTOE_MULT ≥ 0.5`).
- **Hearing in `updateBig`**: fields on `big` (set in `resetWorld`): `noise`, `hearCd` (s until he hears again), `hearFace` (the angle he turns to), `hearTurnT` (turn time left), `hearRate` (rad/s of that turn), `hearLook` (s he keeps looking). Every frame `hearCd` counts down and **`bigDeaf()`** (not `play`, `pendingWin`, `stun`, `blush`, `slip`, `pushCd`; not `noPush`) → `stopHearing()` (noise, turn and look to 0). **`bigListens()`** = `!bigDeaf()` — the one gate for `hearNoise`, the tap-tap lines and the careful autopilot's tiptoe. When he sees someone (`target`) the turn and look are dropped, the noise decays and the chase runs as before — `hearNoise` is not reached. Otherwise **`hearNoise(dt)`** runs before the search/look/patrol branches, so he still hears while he `search`es (a run decision: gating `search` too turned two balance targets red): while `hearCd ≤ 0` and `bigListens()` it sums `NOISE_RATE × dt × audible(l)` over all Little Ones. **`audible(l)`** = 0 unless `isRunning`, no cloak, not `inSafe`, within `HEAR_RADIUS × CELL` and at an angle ≥ `VISION_HALF` from `big.dir`; then 1 with `los` on the sight grid, else `HEAR_WALL`. Something heard → added; nothing heard (also during the cooldown) → `noise` decays by `NOISE_DECAY × dt`. At `NOISE_TURN` with a loudest runner (largest share, tie → nearest): `noise = 0`, `hearCd = HEAR_COOLDOWN`, `hearFace`, `hearTurnT = HEAR_TURN_TIME`, `hearRate`, `hearLook = rand(HEAR_LOOK)` (a gameplay `rng()` draw), `state = "look"`, `timer ≥ turn + look`, goal and path cleared; event `heard { who, kind }`; a player with `!heardHintDone` starts the hint. ## Coins economy (SPEC-009)
- **Ledger**: **`addCoins(reason, amount)`** and **`spendCoins(item, amount)`** (progress section) are the only code that changes `progress.coins`. `addCoins` clamps the amount so the coins never go below 0, skips 0, adds, `logCoins(reason, amount)`, saves, returns what it added. `spendCoins` returns `false` and changes nothing when the coins are short; else subtracts, logs `buy:<item>` with the negative amount, saves, returns `true`. `logCoins` pushes the `coins` event into `events` (via `logEvent`) and a copy into **`ledger`** — the session list since page load (not cleared by `startGame`, capped at `CFG.EVENT_LOG_MAX`; `__bb.ledger()` returns copies). Callers: `giveReward`, `updateStars`, `buyGloves`/`buyKisses`/`buyRescueKit` (`spendCoins(kind, price)`), `buyLook` (`spendCoins("<slot>:<id>", price)`), `buyUpgrade` (`spendCoins("upgrade:<key>", price)`). Reasons: see the event log.
- **Source scan**: `tests/economy.spec.js` "only the ledger writes coins" (`@fast`, Node, `coinWrites(src)`) fails on any write to a `coins` member outside the bodies of `addCoins`/`spendCoins` — `=`, compound `op=`, `++`/`--`, `["coins"]`, aliases, destructuring targets, `Object.assign(…, { coins })`, `Reflect.set`/`Reflect.defineProperty`/`Object.defineProperty`, and `progress = …` other than `freshProgress()` / `loadProgress(…)` or a `...progress` spread; it plants one write of each kind to prove the scan finds it. Tests may still set `__bb.progress.coins` as setup.
- **Reward** (`giveReward(win)`): `rewardBase(world, n)` = `REWARD.BASE + PER_LEVEL × n + PER_WORLD × worldDifficulty(world)` (SPEC-016: by the difficulty index, 0–4); the fast star needs `stats.time ≤ fastTarget(world, n)` = `CFG.FAST_TIME(n) + worldDifficulty(world) × CFG.FAST_PER_WORLD` (also read by `scripts/balance.js`). Win: `first = !worldProgress().won[n]`; the line = `max(base, FIRST_MIN)` or `max(floor(base / 2), REPLAY_MIN)`; `restCut = min(rests × CFG.COINS_PER_REST, line − floor)`, so the shown lines always add up; `newStars = max(0, stars − previous best)` × `REWARD.NEW_STAR`; `hugs = stats.playerHugs × REWARD.PER_HUG`. Every part except `star` goes through `addCoins` (one ledger entry per line); stars, `won[n] = true` and `unlocked` are written to the current world. `lastReward` = `{ win, coins, starCoins, stars, nobodyOut, fast, target, first, base, newStars, newBest, world, level, worldDone, parts, bonusUnlocked }` (SPEC-016: `bonusUnlocked` = this win opened the bonus worlds). Not a win: `addCoins("hugs", …)`, `lastReward = { win: false, coins, starCoins, parts }`.
- **Reward lifecycle**: **`rewardDue`** = a level is running and not paid yet: `startGame` sets it; `giveReward`, `resetProgress` and `__bb.setProgress` clear it. **`leaveLevel()`** (first thing in `startGame`, `toMap` and `toHome`; so pause → Map or Home, a restart, the next level) does nothing unless `rewardDue` and the mode is `play`/`pause`; with `pendingWin > 0` (the last heart is gone, the final hug still playing) it clears `pendingWin`, logs `win` and pays `giveReward(true)`; otherwise `giveReward(false)` (hugs only). - **Wardrobe**: hats/jackets/pants/Big One looks have `id` and `price` (`tierPrice(0…3)`, 0 = free; hairs are always free). **`skinSel`** = what is shown (may include a locked item while trying on), **`skinKeep`** = the last own look (owned or free): `bebebe-outfits` stores `skinKeep` (`saveSkins`) and a level starts with it. `ownsItem(slot, idx)` = free or the id is in `progress.owned[OWN_KEY[slot]]`. `cycleOutfit`/`cycleBig` move `skinSel`; an owned item goes into `skinKeep` at once. `tryingOn` (`updateTryOn`) = some column (`p1`, `p2`, `big`) shows a locked item; `lockedItems(key)` / `lockedPrice(key)`. **`buyLook(key)`**: short of coins → `buyArmed = null`, `SFX.out`; first call arms (`buyArmed = key`), the second buys every locked item of that column through `spendCoins` and moves them into `skinKeep`. **`endTryOn()`** (from `startGame` and from `frame()` outside the Wardrobe tab — `!inWardrobe()`, SPEC-017) puts `skinSel` back to `skinKeep`. `randomOutfit` picks only owned items; `botOutfit(i)` may use any. `fitOutfitsToOwned()` (after `resetProgress`, or at start for a save that has `owned`) replaces a not-owned kept item with its `DEFAULT_SKINS` one. `resetOutfits()` (tests) = default looks, nothing tried on.

## 3D look (SPEC-021)
- **Outlines**: `part(geo, color, outline, mat)` grows an inverted hull by `outline × CFG.OUTLINE_LOOK.k` per axis; with `CFG.OUTLINE_WOBBLE` each axis gets ±`wobble` and the hull is shifted by ±`shift` of the thickness (one side of the line thicker). The randomness is its own `mulberry32` (`wobbleSeed(0)` per map build, `wobbleSeed(1)` per character build) — never the game `rng()`. Hulls carry `userData.hull` (the asked thickness) for `look3D`. 3D ink is `INK3` (`#1b1b1b`); the 2D layer keeps `OUT`.
- **Materials**: one 2-tone `gradTex` (`TOON_LOOK.tones`), `MeshToonMaterial` everywhere (no specular); sun shadows `TOON_LOOK.shadow` (intensity) and `shadowRadius`. **Hatching**: `addHatch(m)` patches the toon shader (`onBeforeCompile`, one program, `customProgramCacheKey "hatch"`): world-space diagonal stripes on faces turned less than `HATCH_LOOK.side` to the sun (full strength away from it, `lit` share on lit sides); it logs `console.error` if three.js chunks change. Walls (`toonH`), houses, cottages and roofs use it (`HATCHED` pieces).
- **Ground**: `paintGround` paints the one ground canvas per level build: base + checker, **`markerStrokes(rnd, colours, rect?)`** (diagonal strokes batched into a few `Path2D`s), **`groundDoodles`** per world (`GROUND_LOOK.doodle`), the mud ring around the dad's house, then the floors (plain: `levels.spec` samples square/bridge colours). Seeded (`GROUND_LOOK.seed`, world, level); no image files, no new textures.
- **Paper grain**: `makePaperGrain()` draws a 256² canvas once (`PAPER_GRAIN_LOOK`); `paperMesh` is a full-screen quad drawn last in the 3D scene with `MultiplyBlending` (a CSS `mix-blend-mode` layer cost ~+20–30 % frame time). `syncPaper()` each frame only compares: `CFG.PAPER_GRAIN` and, on a phone, `CFG.PAPER_GRAIN_PHONE` (off by default); the tile follows the pixel ratio.

- **SPEC-020 art in `sw.js`**: the cache is named **`SW_VERSION + "-" + ASSETS_HASH`** (`CACHE`); `ASSETS_HASH` (a hash of the sprites' bytes) and `PRECACHE_ASSETS` are written by `npm run assets`, so a redrawn sprite gives a new cache (activate deletes the old one) without a `SW_VERSION` bump. The core list (`PRECACHE_LOCAL` + three.js) is added all-or-nothing; the sprites afterwards one by one (`cache: "no-cache"`, errors ignored). `/assets/` is cache-first, like `/icons/`.
- **Registration guard** (`registerServiceWorker()`, main loop section, after `__bbReady`): only on `http:`/`https:` with `navigator.serviceWorker`, inside `try/catch`, rejected promise swallowed — nothing happens on `file://` or in the claude.ai page.
- On iOS the home-screen app has its own `localStorage`, separate from Safari.

## Tests and CI (SPEC-023)
- **Two kinds of tests.** *Rendered* tests open the game normally (`openGame(page)`) and check what is drawn: HUD, menus, phone layouts, banners, the 3D map pieces, screenshots, sounds. *Sim* tests open it in sim mode (`openGame(page, { sim: true })`: no 3D, no 2D drawing, no audio, the frame loop does not play) and check logic and numbers only, advancing the game with `step()` / `__bb.update` / `__bb.simRun`. Sim tests: all of `balance.spec.js` and `i18n.spec.js`, the rule tests of `gameplay.spec.js`, the ledger/reward/wardrobe-data/save tests of `economy.spec.js`, the invariants (except the drawn shop), the generator tests of `levels.spec.js` (the `levelPage` fixture), the names save test. Shared-page specs have two fixtures: `page` (rendered `sharedPage()`) and `simPage` (a second `sharedPage()` in sim mode; a sim page draws nothing, so it may stay open next to the rendered one); `levels.spec.js`'s `levelPage` is a sim page, `names.spec.js` gets a fresh `simPage`.
- **Sim guard (AC 5).** In sim mode `frames(page)` and `page.screenshot()` (patched by `openGame` for sim pages) throw "sim mode: …", and `window.__bb` is a `Proxy` that throws on reading any name in `__bb.SIM_DRAWN` (the per-frame drawn state: `buttonRects`, `buttonNames`, `tapButton`, `hudRects`, `mapInfo`, `levelCard`, `storyInfo`, `textSizes`, `minimap`, `bannerRect`, `rotateShown`, `winPanel`, `winLine`, `bonusNote`, `shopLayout`, `kitHint`, `heardHint`, `edgeArrows`, `stickMarks`, `tapLines`, `installHintShown`, `mapPieces`, `groundColorAt`, `camera`, `minimapAlpha`, `look3D`). A visual test opened in sim fails loudly instead of checking stale or empty state. Tests: `balance.spec.js` "drawing helpers and drawn state throw in sim mode"; `smoke.spec.js` "every __bb getter is drawn state (SIM_DRAWN) or listed logic state" (a new getter must go into `SIM_DRAWN` or the test's `LOGIC_GETTERS`). `smoke.spec.js` "the gameplay states the sim tests build draw without errors" draws, on a rendered page, the states the moved rule tests build (kiss in flight, blush, throw-out, down + kit, bonus star, every level type).
- **CI order rule.** CI runs every file with `fullyParallel` in 4 shards, so a shard may start in the middle of a file: no test depends on the one before it (each fixture resets the shared page), a spec with a shared page closes it in a top-level `test.afterAll`, and at most one **rendered** shared page is open at a time (sim pages draw nothing and may stay open beside it).
- **Test environment** (`tests/test-env.js`, used by `playwright.config.js`, `tests/global-setup.js`, `scripts/balance.js`): WebGL backend `PW_GPU` = auto (GPU locally: `--use-gl=angle --use-angle=d3d11` on Windows, `metal` on macOS, `gl` on Linux; SwiftShader on CI) / `0` (SwiftShader) / `1` (GPU, no fallback). In auto mode the global setup probes the GPU once; no hardware WebGL context → `PW_GL=swiftshader` (workers load the config again and see it) and one console line. Priority: the global setup and `scripts/balance.js` call `lowerPriority()` (below normal; `PW_NICE=0` off); workers and browsers inherit it, except Chrome's GPU process on Windows, which raises itself to "Above normal" — so locally on Windows the browser gets `--in-process-gpu` (GPU work inside the below-normal browser process). `tests/env.spec.js` checks the renderer string against the backend, the worker's priority and (Windows) every browser process's priority.
- **Failure screenshots** (`tests/pw.js`: every spec requires `./pw` instead of `@playwright/test`): when a test fails, its own page and every page still open in the worker's browser (the shared pages) are screenshotted and attached (sim pages skipped). Free when tests pass; `screenshot` in the config stays `off` (SPEC-018).
- **CI.** `.github/workflows/tests.yml` — on push to `SPEC-*`, `workflow_dispatch`, and `workflow_call` from `pages.yml`: 4 shard jobs (`--shard i/4`, blob reporter; Playwright browsers cached by version; artifacts `blob-report-<i>`, and `test-results-<i>` = error context + failure screenshots on failure; `overwrite: true`; a newer push of the same branch cancels the older run, calls from `pages.yml` are never cancelled), then `report` merges the blobs into one HTML report (artifact `html-report`) and fails if a shard failed. `pages.yml`: job `test` = `uses: ./.github/workflows/tests.yml`, then `deploy` (unchanged copy of the site files). `.github/workflows/balance.yml` — `workflow_dispatch` with input `ref` (and a push to `SPEC-*` that changes the file itself): `npm run balance`, artifact `balance` = `balance.md` + `balance.json`.

## Save data (localStorage)
- `bebebe-progress` (SPEC-006, SPEC-009, SPEC-016, SPEC-022 `seen`): SPEC-022 adds `seen: { intro, boss_park, boss_field, boss_city, boss_school, bonus_beach, bonus_winter, ending }` (`cleanSeen`: only `true` counts, unknown keys dropped, missing or broken → all `false`; fixture `pre-spec-022.json`). `{ worlds: { park|field|city|school|beach|winter: { unlocked: 1..20, stars: { [n]: 1..3 }, won: { [n]: true } } }, lastWorld, coins, inv: {mittens, mega, kisses, rescues}, equip: [p1, p2], owned: { hats: [id], jackets: [id], pants: [id], big: [id] }, upgrades: { fastFeet, longItems, quickHelp } }`. The flat fields are left out of the result, and a migrated save is written back once on load. Coins, inventory, equip and names are untouched. `giveReward` writes stars/`won`/`unlocked` only into `worldProgress()` (the current world) and sets `lastWorld`; coins — see Coins economy; fast time `fastTarget(world, n)` (by the difficulty index). Needs a real reload: outfits are not part of `loadProgress`. `bebebe-place`: no longer read (SPEC-006: the place is the world); old saves may still have it. `bebebe-lang`: `en|es|ru`. - `bebebe-names` (SPEC-003): `{ p1, p2, big, bots: [b1, b2, b3, b4] }` — only typed names, `""` = language default; every field cleaned on load, missing or broken data → defaults.
