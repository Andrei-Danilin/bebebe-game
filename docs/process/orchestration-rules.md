# Run sizing and rules for spec runs (bebebe-game)

Adapted from ce-fsa-app's orchestration rules (2026-11-21), with two differences agreed by Andrei:
**Claude Code commits and merges itself**, and **Sonnet writes the code while Opus orchestrates and checks** (Andrei, 2026-11-26; before that every role ran on Opus). Every run prompt follows these rules; a prompt may only tighten them.

## 1. Size the spec first (the spec's `Complexity:` line decides; when unsure, the smaller tier)

| Tier | What it is | Roles | Review | Target |
|---|---|---|---|---|
| **S** | one rule or number, one item, one text/visual tweak | **Opus** orchestrator + **Sonnet** implementer (`general-purpose`) | one `code-reviewer` (opus) | 20–40 min |
| **M** | several related items, a new screen, a new item type or place | **Opus** orchestrator + **Sonnet** implementer (`general-purpose`) | `code-reviewer` + `architect-reviewer` (opus, parallel), one pass; one `code-reviewer` check of the fix commits | 45–90 min |
| **L** | new game system (economy, progress format, level generator, AI behaviour), a big refactor (e.g. splitting `index.html`) | **Opus** orchestrator + **Sonnet** implementer | `code-reviewer` + `architect-reviewer` (opus, parallel), one pass; one `code-reviewer` check of the fix commits | 2–3 h |

**Models (Andrei, 2026-11-26):**
- **Opus** — the main session (orchestrator: plans the steps, briefs, reads every implementer diff against the spec before CI, decides) and the reviewers `code-reviewer` and `architect-reviewer`. The orchestrator writes no production code.
- **Sonnet** — the code: the implementer is `general-purpose` started with `model: "sonnet"` (kept for its fix rounds via SendMessage); also `tester` (runs tests and CI, reads artifacts) and `doc-keeper` (docs), whose agent files say `model: sonnet`.
- **Escalation:** if the Sonnet implementer fails the same step twice (tests still red, or the orchestrator's diff check finds the AC not met), the orchestrator may brief a fresh `general-purpose` with `model: "opus"` for that one step only, and says so in the report.
Start every run with `claude --model opus`; the first step of every run is `npm run claude:sync` (agents and skills from `claude-setup/` into `.claude/`).

## 2. Tests
- TDD: each acceptance criterion gets a Playwright test that fails before the change (the run report names it).
- **Speed rules (Andrei, 2026-11-23): no local whole suite.** Locally only **`npm run test:fast`** (the `@fast` set, one test per area, ~1.5 min) **plus the test files of what changed** (`npx playwright test tests/<file>`, or `-g "<name>"`). Phone layouts locally at **667×375 only** (`-g "667"`); CI runs all sizes. A new test that guards a whole area may get `{ tag: "@fast" }`; keep the set under 2 min. Local runs use the GPU and below-normal priority (SPEC-023: `PW_GPU`, `PW_NICE`, see `README.md`).
- **The whole suite runs on CI** (SPEC-023, `.github/workflows/tests.yml`, 10 shards packed by measured time: `scripts/shards.js`, `tests/shards/plan.json`; a new or renamed test needs `npm run shards`): push the spec branch (`git push -u origin <branch>`; never `--force`, never other people's branches), find the run of exactly that commit (`gh run list --workflow tests.yml --commit $(git rev-parse HEAD) --limit 1`, retried every ~10 s until it appears) and `gh run watch <id> --exit-status`. Red → investigate from its artifacts (`gh run download <id>`: `html-report` = merged Playwright report; `test-results-<n>` = error context + failure screenshots of the failing shard), fix, push again. **The merge happens only when the Tests run of the branch's last push is green.** The Pages workflow tests `master` again (the same sharded jobs) before the deploy; no local run on `master`.
- **CI fonts locally (SPEC-033, D-3):** CI draws text in DejaVu Sans, wider than the Windows/macOS fonts, so a text that fits here can misfit there (the first SPEC-033 CI run was red for exactly that, twice). `PW_FONT=ci` makes the local browser use the same font (`tests/ci-font.js`, `tests/fonts/`: test-only, not in the site): run the changed text / layout tests with it (`PW_FONT=ci npx playwright test tests/<file> -g "…"`; phones `-g "667"`) and fix a red at the root with margin (font scale ×1.15 / ×1.3 in the test, not a wider box for one language). It does not replace CI's emoji font. **CI keeps `retries: 0`** (D-15, SPEC-033): a flaky test is fixed at the root, never retried.
- Logic-only tests open the game in sim mode (`openGame(page, { sim: true })`, no 3D, no audio); tests that check what is drawn stay rendered (see `docs/architecture.md` "Tests and CI", incl. the CI order rule: no test depends on the one before it, a shared page is closed in a top-level `test.afterAll`).
- A rule decided by the kids is pinned by a test in `tests/gameplay.spec.js`; changing such a test needs the spec to say the rule changes.
- **Balance (SPEC-008, on GitHub since SPEC-023):** a spec that changes gameplay numbers or rules gets the report from the Balance workflow before the merge — `gh workflow run balance.yml -f ref=<branch>`, `gh run list --workflow balance.yml --limit 5` → the run titled `Balance <branch>` created after the dispatch for the id, `gh run watch <id> --exit-status`, `gh run download <id> -n balance -D reports` — commits the updated `reports/balance.md` + `reports/balance.json` on the branch, and lists the red targets in its final report (red is not a stop by itself unless the spec's ACs say so). The report plays every level with the autopilot in sim mode; its targets live in `CFG.BALANCE`. A changed number in `CFG`/`GLOVES`/`KISSES`/`RESCUE_KIT` also needs `npm run docs:numbers` (the numbers section of `game-design.md` is generated; `tests/invariants.spec.js` fails when it is stale).
- Visual work: one screenshot per new screen/place via `page.screenshot` in a throwaway script (not committed), looked at before the review.
- Never paste full test logs into reports: counts, failing test names, the first assertion line.
- Keep tests fast (SPEC-018, numbers in `reports/test-times.md`): an `evaluate` never returns a game object (a mutating body goes in braces; a smoke test guards it); checks inside loops go through `softly()` or a problem list with one `expect` at the end; no real waits for game logic; no second game page left open while other tests run.


## 3. Context and output discipline
- Brief agents with **paths**, not pasted documents: the spec path, `CLAUDE.md`, `game-design.md`, `architecture.md`, the diff.
- Read only the code you need: `architecture.md` names the module (`src/core/…`, `src/i18n.js`, `src/story.js`, `src/client/…`) and the symbol for each area (the module table); never a whole directory. `index.html` is only the shell.
- A change in `src/` is followed by `npm run precache` (module hashes in the import map and `sw.js`; `tests/pwa.spec.js` fails on stale ones), also after merging `master` into the branch.
- Reports are tables and short lines: AC → test, counts, findings by severity, open points.

## 4. Decisions and scope
- All decisions are taken **before** a run (they are in the spec). Anything that comes up during a run goes to `specs/BACKLOG.md`.
- Reviews: **one pass** on the spec and `git diff master...<branch>` (tier S: `code-reviewer`; M and L: `code-reviewer` + `architect-reviewer` in parallel), **one fix round, plus one check of the fix commits** (`code-reviewer` on those commits only); a CRITICAL/HIGH left after that stops the run before the merge (branch kept, reported).
- **Queues:** the next spec may start while the previous spec's Pages deploy is still running; its tests must be green before the next spec's own merge (check the Pages run of `master`'s last commit: `gh run list --workflow pages.yml --commit $(git rev-parse origin/master) --limit 1`; a cancelled run was superseded — look at the last commit's run). A red deploy with green tests is recovered with a fresh `gh workflow run pages.yml --ref master`; a deploy-only failure with green tests does not block the next spec (Andrei).
- Small specs of the same area may share one branch (one review, one test pass) only if the run prompt says so.

## 5. Git (this repo: Claude Code commits and merges)
- Branch `SPEC-NNN-short-description` off `master`; commits `SPEC-NNN: <what>` with explicit paths and the attribution lines from the system reminder; the machine's git identity, never changed.
- Remote `origin` = `github.com/Andrei-Danilin/bebebe-game` (public). **Pushing spec branches is allowed** (SPEC-023) so CI can test them: `git push -u origin <branch>` — only your own `SPEC-*` branch, never `--force`, never other people's branches.
- **Close on the branch, before the merge** (close and merge go out in one push): docs commit, then the spec's `Status:` becomes `done (merged by "Merge SPEC-NNN", see git log)` (the merge hash does not exist yet), the file moves to `specs/_archive/`, the run-state file is deleted; commit `SPEC-NNN: close`; before the push, bring `master` in if it moved on — `git fetch origin && (git merge-base --is-ancestor origin/master HEAD || git merge origin/master)` (never rebase), so the merge result itself is tested; push the branch once — its Tests run (found by commit) must be green.
- Merge: `git checkout master && git merge --ff-only origin/master && git merge --no-ff <branch>` (`Merge SPEC-NNN: <title>`) only after the branch's Tests run is green and the review has no open CRITICAL/HIGH; `git branch -d` the spec branch (no local suite on `master`, see §2).
- After the merge: `git push origin master` (never `--force`), `git push origin --delete <branch>` (the remote spec branch), then find the Pages run of that commit (`id=$(gh run list --workflow pages.yml --commit $(git rev-parse HEAD) --limit 1 --json databaseId --jq '.[0].databaseId')`, retry until it appears) and `gh run watch $id --exit-status` until it (sharded tests + deploy) is green (a cancelled run = superseded by a newer push: watch the run of the last commit); a red deploy is reported, not retried blindly. The `deploy` job tries `deploy-pages` twice by itself and then checks that the live site serves the commit (SPEC-011). A red deploy **with green tests** (e.g. "Fetching artifact metadata failed"): recover it once with `gh run rerun <id> --failed` only when that run's `build` job was green and its commit is still the HEAD of `origin/master` (it reruns only `deploy`, which deploys the artifact `build` uploaded once); otherwise a fresh `gh workflow run pages.yml --ref master`.
- No `reset --hard`, no `branch -D`, no history rewrite on `master`.
- **A deploy that breaks the game for the kids (D-7, Andrei 2026-11-26):** `git revert -m 1 <merge sha>` (message `revert: <what>`) may be pushed **straight to `master`** — no spec branch; the Pages workflow still runs the sharded tests before it deploys, so a red test still stops it. Or redeploy a known-good tag at once: `gh workflow run pages.yml --ref master -f ref=vX.Y.Z` (`docs/release.md` "Rollback"; the `ref` input defaults to `master`). Watch the run (`gh run watch`), report it, and follow with a normal spec for the real fix. Everything else still goes through a spec branch.

## 6. Documentation
- `doc-keeper` (before the close, on the branch) updates `docs/game-design.md` when a rule or number changed, `architecture.md` when a section, state or `__bb` field changed, `README.md` when a player-facing feature or command changed. Commit `SPEC-NNN: docs`.
- `game-design.md` is mirrored in the claude.ai project doc `claude/game-design.md` by the spec author after the run.
