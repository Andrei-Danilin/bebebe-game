# SPEC-011 — Split index.html into ES modules (core / client)

Status: ready
Complexity: L
Branch: SPEC-011-modules
Decided by: Andrei (2026-11-22): the game goes online (SPEC-012…015) and later to Google Play / App Store, so the game logic must run in the browser **and** on a Node server; `index.html` is split into modules, the game opens only over http (`npm run serve`, GitHub Pages, the installed app), opening by double-click from disk and publishing as one claude.ai page are dropped. Module layout, rules and checks: Claude (spec author).

## Description
Nothing changes for the player. Under the hood the ~4,900-line `index.html` (from review: 9,387 lines at a52ecec — 2D layer 2,705, 3D layer 2,245) becomes a small shell plus ES modules in `src/`: `src/core/` is the game itself (rules, level generator, bots, the Big One, difficulty) and knows nothing about the screen; `src/client/` is everything a person sees, hears and touches (3D, 2D UI, input, sound, saves). This is the first step of the online game: the server will run `src/core/` (SPEC-012, SPEC-013).

## Goal
- `src/core/` imports nothing from `src/client/`, never imports three.js and loads in plain Node without errors.
- The game plays exactly as before: same levels, same event log for the same seed and inputs, whole suite green.
- The installed app (PWA) still works offline and updates cleanly.
- No file is a second `index.html`: the big sections each get their own module.

   - `index.html` stays **network-first exactly as today**: an online launch gets the new version at once, offline the cached one (`tests/pwa.spec.js` "index.html is network-first…" stays green **unchanged**).

So a shell can only load its own module versions: a new shell asks for new URLs (no mix, and no stale CDN edge, because the URL changed), an old cached shell keeps its old URLs. No dynamic `import()` in the game.

Separate caches: shell + `src/` by `SRC_HASH`, sprites by `ASSETS_HASH`, three.js by its version — a code deploy re-downloads no sprites. Versioned module URLs are served cache-first; the service worker writes into the `src` cache only at install (no runtime writes), and deletes an old cache only when no page of that version is open (or keeps the last 2).
