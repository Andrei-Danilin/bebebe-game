# SPEC-001 — Installable PWA on GitHub Pages (iPhone home screen, offline)

Status: ready
Complexity: M
Branch: SPEC-001-pwa-github-pages
Decided by: Andrei (2026-11-21): public repo `Neasit/bebebe-game`; Claude Code creates it with `gh`; after this spec every merge to `master` is pushed and deployed; the game must work offline after the first open. Everything else below: Claude (spec author).

## Description
Andrei wants to put the game on his iPhone like an app. The game is published on GitHub Pages at `https://neasit.github.io/bebebe-game/`, can be added to the iPhone home screen from Safari (Share → Add to Home Screen), opens full screen without the browser bar, has its own icon, and keeps working with no internet after the first open. Every merge to `master` publishes the new version automatically.

## Goal
- The repo is on GitHub (`Neasit/bebebe-game`, public), Pages serves the game from a GitHub Actions workflow that runs the tests first.
- Opening the URL on an iPhone in Safari and adding it to the home screen gives a full-screen app with the game's icon and name.
- In airplane mode the installed app still starts and plays (game + three.js come from the service-worker cache).
- The game still opens from disk by double-click and still publishes as a claude.ai page (no service worker there, no errors).

## Context
- `index.html` is the whole game (one ES module, three.js `0.187.0` imported from jsDelivr: `three.module.js`, which imports `./three.core.js`). `docs/architecture.md` has the section map; `fit()` (screen section) sizes the canvases from `window.innerWidth/innerHeight`; the HUD has a fullscreen button (`toggleFullscreen`, 2D layer section); `isTouch` exists; there is a rotate hint for portrait.
- `localStorage` keys: `bebebe-progress`, `bebebe-outfits`, `bebebe-place`, `bebebe-lang`. On iOS a home-screen app has its own storage, separate from Safari: progress from Safari does not carry over (expected; mention it in README).
- Tests open `index.html` from `file://` and route jsDelivr to `node_modules/three/build` (`tests/helpers.js`). There is no git remote yet; `CLAUDE.md` currently says "no push".
- iOS specifics to respect: the home-screen icon comes from `<link rel="apple-touch-icon">` (180×180 PNG, no transparency); `display: standalone` in the manifest plus `apple-mobile-web-app-capable` / `apple-mobile-web-app-status-bar-style` / `apple-mobile-web-app-title` metas; iPhone has no Fullscreen API; manifest `orientation` is ignored on iOS (keep the rotate hint); the notch/home indicator need `viewport-fit=cover` with `env(safe-area-inset-*)` padding; Web Audio starts only after a touch (already done in `initAudio` on `pointerdown`) and is silent when the ring/silent switch is on.

## Out of scope
- Android-specific install prompts (`beforeinstallprompt` UI) — the manifest makes it installable there anyway; no custom button.
- Push notifications, background sync, app-store packaging.
- Moving progress between Safari and the installed app, or between devices (BACKLOG).
- Changing any game rule, screen layout (other than safe-area padding and the hidden fullscreen button) or text other than the new install hint.
- Splitting `index.html` into modules.

## Acceptance criteria
1. **Manifest.** `manifest.webmanifest` at the repo root, linked from `index.html` (`<link rel="manifest">`), with `name` "BeBeBe Atrapar", `short_name` "BeBeBe", `start_url` "./", `scope` "./", `display` "standalone", `orientation` "landscape", `background_color` and `theme_color` "#2b3a2e", icons 192×192 and 512×512 PNG (`purpose` "any") and 512×512 maskable PNG (`purpose` "maskable"). → test `tests/pwa.spec.js` "manifest is linked and complete"
2. **Icons.** `icons/` holds `icon.svg` (source: a cartoon Big One face with a pink heart on a green round-rect background, kid-friendly, readable at 60 px), `apple-touch-icon.png` (180×180, opaque), `icon-192.png`, `icon-512.png`, `icon-512-maskable.png` (content inside the central 80 % safe zone), generated by `scripts/make-icons.js` (renders the SVG with Playwright; run with `npm run icons`). Every PNG has the size its name says. → test "icons exist with the right sizes"
3. **iOS metas.** `index.html` `<head>` has `<link rel="apple-touch-icon" href="icons/apple-touch-icon.png">`, `apple-mobile-web-app-capable` "yes", `apple-mobile-web-app-status-bar-style` "black-translucent", `apple-mobile-web-app-title` "BeBeBe", and the viewport meta includes `viewport-fit=cover`. → test "iOS home-screen metas are present"
4. **Safe areas.** With `viewport-fit=cover`, the game area never sits under the notch or the home indicator: `body` gets `env(safe-area-inset-*)` padding and `fit()` sizes the canvases from the space left inside that padding (not from raw `innerWidth/innerHeight`). On desktop (insets 0) the size is unchanged. → test "game fills the viewport minus the safe-area padding" (emulate a padding via a test-only CSS variable or check that `fit()` uses the parent's client box)
5. **Service worker.** `sw.js` at the repo root with a `SW_VERSION` constant. On `install` it precaches `./`, `./index.html`, `./manifest.webmanifest`, the icon files and the two three.js files from jsDelivr (`https://cdn.jsdelivr.net/npm/three@0.187.0/build/three.module.js` and `.../three.core.js`, fetched with `mode: "cors"`). Fetch strategy: navigation and `index.html` **network-first** with cache fallback (so a new version shows up as soon as the phone is online); jsDelivr three.js and icons **cache-first**; everything else network with cache fallback. `activate` deletes caches of other versions and calls `clients.claim()`; `install` calls `skipWaiting()`. → tests "service worker registers and controls the page over http", "old caches are removed on a new SW_VERSION"
6. **Registration guard.** `index.html` registers `sw.js` only when `location.protocol` is `http:` or `https:` and `navigator.serviceWorker` exists, inside `try/catch`, after the game is ready; on `file://` and inside the claude.ai page (where registration is refused) nothing breaks and no error is logged. → existing smoke tests stay green (they run on `file://`); test "no service worker and no errors on file://"
7. **Offline.** After one online visit over http, with the network off (`context.setOffline(true)`), reloading the page reaches `window.__bbReady === true` and `startGame(1)` + 5 s of `update()` run without page errors. → test "the game starts offline after the first visit"
8. **Standalone mode.** A helper `isStandalone()` (true for `navigator.standalone === true` or `matchMedia("(display-mode: standalone)").matches`, and, for tests only, the URL query `?standalone=1`) hides the HUD fullscreen button (iPhone has no Fullscreen API) and the install hint. → test "fullscreen button is hidden in standalone mode"
9. **Install hint.** On iPhone/iPad Safari when not standalone (`/iPhone|iPad|iPod/` in the user agent, or iPadOS desktop UA with touch), the menu shows one line under the controls text: the `installHint` string (table below), in all three languages; nowhere else. → test "install hint shows on iPhone Safari only" (emulate the iPhone UA with `test.use({ userAgent })`, and `?standalone=1` for the negative case); `tests/i18n.spec.js` stays green
10. **Local http server for tests.** `scripts/serve.js` (Node built-ins only) serves the repo root with correct MIME types (`.html`, `.js`, `.mjs`, `.webmanifest` → `application/manifest+json`, `.png`, `.svg`, `.json`) on a port from `PORT` (default 8123). `playwright.config.js` starts it as `webServer` for the PWA tests; the `file://` tests keep working unchanged. In the PWA tests jsDelivr is routed to `node_modules/three/build` at **context** level (so service-worker requests are intercepted too; if Chromium needs it, set `PW_EXPERIMENTAL_SERVICE_WORKER_NETWORK_EVENTS=1` in the config and say so in the test notes). → all PWA tests above
11. **GitHub repo.** `gh auth status` succeeds (otherwise stop before the merge and report: Andrei runs `gh auth login`). Create `Neasit/bebebe-game` as a **public** repo with description "BeBeBe Atrapar — a 3D arcade game designed by kids", add it as `origin`, push `master` (the whole history). Enable Pages with the GitHub Actions source (`gh api -X POST repos/Neasit/bebebe-game/pages -f build_type=workflow`, or the PUT variant if Pages already exists). → checked in the run report (`gh repo view`, `gh api repos/Neasit/bebebe-game/pages`)
12. **Deploy workflow.** `.github/workflows/pages.yml`: on `push` to `master` and `workflow_dispatch`; job `test` (ubuntu-latest, Node LTS, `npm ci`, `npx playwright install --with-deps chromium`, `npx playwright test`); job `deploy` (`needs: test`) copies only the site files — `index.html`, `manifest.webmanifest`, `sw.js`, `icons/`, `v1-2d/` — into `_site/` and publishes with the current major versions of `actions/configure-pages`, `actions/upload-pages-artifact`, `actions/deploy-pages`; `permissions: contents: read, pages: write, id-token: write`; `concurrency: group: pages, cancel-in-progress: false`. Tests, docs, specs, `claude-setup/`, `node_modules/` are never published. → after the push: `gh run watch` green; `curl -sI https://neasit.github.io/bebebe-game/` is 200 and `.../manifest.webmanifest` is 200 with `application/manifest+json`; `.../tests/` is 404
13. **Git rules updated.** `CLAUDE.md`, `docs/process/orchestration-rules.md` §5 and `RUN_S/M/L.md`: remote `origin` = `github.com/Neasit/bebebe-game`; after a merge and a green whole suite on `master`, `git push origin master` (only `master`, never `--force`, never spec branches), then `gh run watch` until the deploy is green; a red deploy is reported, not retried blindly. Hard rule 1 becomes: "No build. The site is `index.html` + `manifest.webmanifest` + `sw.js` + `icons/` (+ `v1-2d/`); the game still opens from disk by double-click." New hard rule: "`sw.js` `SW_VERSION` is bumped when the precache list or a cache strategy changes (a change to `index.html` alone needs no bump: it is network-first)."
14. **Docs.** `README.md`: the game URL, "Install on iPhone" steps (Safari → Share → Add to Home Screen; works offline after the first open; the home-screen app keeps its own progress, separate from Safari; the silent switch mutes the sound), "Install on Android" (Chrome → Install app). `docs/architecture.md`: a "PWA" section (files, SW strategy, `isStandalone`, registration guard, `SW_VERSION`). `docs/game-design.md` "Платформы": the iPhone app line.
15. **Manual check (Andrei, after the run).** On the iPhone: open the URL in Safari, Add to Home Screen, the icon and the name "BeBeBe" appear, the app opens without the Safari bar, the game plays with touch, sound plays after the first tap; airplane mode → the app still starts. (The run report lists these steps; Claude Code does not mark them done.)
